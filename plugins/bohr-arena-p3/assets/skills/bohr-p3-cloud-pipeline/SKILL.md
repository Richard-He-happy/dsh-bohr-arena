# 云端建包与本地流水线

## 1. 用途与何时使用

题目多（数十道）、每题都要一个可运行 Skill 包时，单靠人写不过来。本期验证的流水线是：**云端 Agent 负责建包，本地负责终检与提交**。

- 适用：批量产包、需要"一个会话产出一个可运行包"、还要保留真实 Agent 原生会话 trace 的场景。
- 不适用：单包手工精修（直接本地写更快）；包内容如何设计见 `bohr-p3-skill-blueprint`。

## 2. 四步流水线（每步留痕、可回滚）

```
① 云端构建  上传 task.md + 构建指南 + 公开接口文件 + 逐题 brief → 云端在 submission/ 写包
② 取回打包  按 submission/SKILL.md 前缀下载产物到 cloud_files/（按白名单清包）
③ 本地终检  本地 Agent 逐项核验（--help、最小 case、空/坏输入、契约回填）→ 最小修复 → 写 VALIDATION.md
            同时产出真实 Agent 原生会话 trace（trace validate 必须通过）
④ 提交      打包 output 目录 + trace + 模型/harness 元数据 → 记录本次提交与包版本
```

一键化：`pipeline` 脚本按 key 串起四步（云构建可跳过复用已有产物、终检可跳过、提交可开关），每题一个工作目录，产物与日志分开存放。

**关键设计**：每一步都可单独重跑；云端失败不影响已有包；提交失败可原样重试（不改包）。

## 3. 云端构建：任务书结构

发给云端 Agent 的提示词应包含 6 段（完整模板见 `references/prompt-templates.md`）：

1. **任务与目标**：题目名 + 一句话目标 + 评测机制（装进官方 Harness，在 3 个隐藏案例上运行，按 rubric 打分；评审看运行产物）。
2. **第一步先写骨架**：`/bohr-workspace/submission/SKILL.md` 先落骨架（frontmatter + 目录），再写脚本——**防 35 分钟超时截断成"没有 SKILL.md 的包"**。
3. **运行契约**：包根、`/input`、`/app/work`、`/app/output`、`result.json` 契约回填、先写 partial、退出码恒 0、纯标准库、不依赖 CWD、预算。
4. **本题特有要求**：逐题 brief 的核心段（必做对象、契约字段、评分点→检查项、失败模式），把"隐藏案例输入推测"也写进去。
5. **规模红线**：SKILL.md ≤12KB、脚本 ≤2 个（各 ≤20KB）、references ≤3、总文件 ≤8、总 ≤150KB。
6. **完成前自检**：`--help` 退出码、eval 等价路径跑通、空/坏输入、报告文件清单+字节数+剩余风险。

**逐题 brief 注入是有效做法**：为每题准备 5–7KB 的 brief（题面特有限制、隐藏输入推测、契约字段、rubric→检查项、校验清单、失败模式），注入后构建 prompt 9–10KB，产包质量明显提升。

## 4. 云端会话要点

| 要点 | 做法 |
|---|---|
| 会话创建 | 显式团队 + cloud 沙箱 + 短超时建会话；失败重试 3 次（间隔 10 秒） |
| 文件上传 | 逐个上传并记录远端路径；只有上传成功的文件才加入 workspace 参数 |
| 超时 | 默认 **55 分钟**（早期 35 分钟会截断在 SKILL.md 之前）；接近尾段仍未完成时，用同会话续跑"收尾指令"再打包 |
| 并发 | **2–3 个**会话；实测 6 个并发全部 502 |
| 串行化 | 多个云端任务并发会触发本地状态锁冲突（表现为 "state.lock: The file exists"）→ 用串行批次脚本 |
| 会话复用 | 每题只用一个 launcher；先检查 session 记录，避免重复建会话 |
| 输出 | 会话回答、workflow 标识、云产物清单都要落盘，便于断点续跑 |

## 5. 取回打包与白名单清包

- **前缀识别**：以云端 `submission/SKILL.md` 的路径为前缀下载；若云端没写 SKILL.md，前缀为空会下载整个工作区（含 upload/demo/临时目录）→ 必须按白名单清包。
- **白名单**：`SKILL.md`、`scripts/*.py`、`references/*`（+ 少量确定性资产）；排除 `__pycache__`、`.pyc`、`demo/`、`test/`、`upload/`、`tmp/`、示例二进制。
- **暂存后替换**（关键）：先下载到暂存目录 → 校验暂存目录里有 `SKILL.md` → 归档旧包（带时间戳）→ 再替换为当前包。**云端失败绝不覆盖已有最佳包**。
- **版本管理**：每题保留"当前最佳包 + 历史版本快照"；回滚 = 把快照目录换回来再提交。

## 6. 本地终检（提交前最后一道闸）

本地 Agent 的任务不是"重写包"，而是**逐项核验 + 最小修复**：

1. 结构：包根 SKILL.md、frontmatter、引用路径存在、文件数与体积。
2. 命令：每个脚本 `--help` 退出码 0；`ast.parse` 通过。
3. 最小 case：造最小 `/input`（`case.json` + 材料 + workorder 形状对象），跑 `init → 写工作稿 → check → build`。
4. 降级：空输入、坏 JSON、缺材料三种情况均产出合法 partial 结果、退出码 0。
5. 契约：`output_contract` 逐键回填（list 型必须逐字段），`case_id` 未丢。
6. 产物：主产物存在且可编辑；导出件真实（PDF 头/PNG IHDR/pptx 可解压）。
7. 只做最小修复（≤3 文件、小改动），并写 `VALIDATION.md` 记录发现与修复。
8. 产出**真实 Agent 原生会话 trace**（`trace validate` 必须通过，事件数与可用事件数记录在案）；trace 不可伪造、不可拼接。

## 7. 提交

- 打包：复制终检后的包到输出目录（再次按白名单排除），记录文件数与字节数。
- 提交命令必须带：题目标识、输出目录、trace、模型、harness 元数据；返回结果落盘（状态、attempt 标识、包指纹）。
- 提交失败处理：先判断是"包问题"还是"平台通道问题"；通道问题不重试到爆，等恢复后原样重提。
- 每次提交都记录到题目的提交清单里，便于算方差与取最好。

## 8. 自动化守护（把重复动作交给脚本）

| 组件 | 频率 | 职责 |
|---|---|---|
| 定时扫描 | 每 15 分钟 | 拉每题状态/分数，写状态日志；发现 failed 自动处理（重提或标记） |
| autoroll | 每约 2 小时 | 挑"有最佳分、低于目标、无 pending、attempt 未超上限"的题，串行执行同包重提 4–6 条 |
| 流水线 launcher | 按需 | 串行跑"云构建→打包→终检→提交"，一个批次不超过并发上限 |
| 批次脚本 | 按需 | 串行处理一组题的同类动作（如 patch 批次），避免云端锁冲突 |

自动化原则：**只做"已验证动作"的重复**（重提、重跑、记录），不做自主改包；所有自动动作写日志、可追溯、可停止。

## 9. 故障与对策（速查）

| 故障 | 现象 | 对策 |
|---|---|---|
| 云端超时截断 | 有 scripts 无 SKILL.md；带 `__pycache__`/demo | 任务书要求先写骨架；超时 55 分钟；同会话续跑收尾 |
| 云端 502 | 返回 HTML 页面而非 API 响应 | 平台侧故障：降并发到 2–3、自动重试（≤3 次、间隔 90 秒）、从上一版包恢复 |
| 本地状态锁冲突 | "state.lock: The file exists" | 串行执行；不要并行启动多个云端任务 |
| 上传通道故障 | 提交报网络超时、平台主 API 正常 | 判定平台上传服务故障：暂停批量提交、每 20–30 分钟单条探测，恢复后集中重提 |
| 前缀识别失败 | 下载了整个工作区 | 按白名单清包；实在没有 SKILL.md 则判失败重跑 |
| 会话重复 | 同题多个会话并行、产物互相覆盖 | 每题一个 launcher；先查 session 记录 |
| 本地校验挂死 | 子进程长时间不退出 | 用超时 + 进程树强杀（实测可挂 20 分钟无输出） |
| PowerShell 执行策略 | 脚本被拦截 | 进程级 Bypass 后再调用；注意不要给内置自动变量赋值 |
| stdout 被污染 | 提交/版本命令的告警混进 JSON 输出 | 解析时先截取第一个 JSON 片段；版本过期立即升级 |
| 包被云产物覆盖 | 旧最佳包丢失 | 暂存目录 + 归档 + 校验后才替换 |

更多细节与恢复顺序见 `references/failure-recovery.md`。

## 10. 自检清单（流水线跑完）

- [ ] 每题工作目录：云产物、包、终检记录、trace、提交记录、提交清单齐全。
- [ ] 云端会话串行、并发 ≤3；无重复会话。
- [ ] 当前包 = 终检通过的包；旧版本有快照可回滚。
- [ ] trace 通过校验，且是真实 Agent 原生会话。
- [ ] 提交结果落盘；失败项已分类（包问题/通道问题）。
- [ ] 自动化日志无异常堆积；autoroll 未超出队列预算。
