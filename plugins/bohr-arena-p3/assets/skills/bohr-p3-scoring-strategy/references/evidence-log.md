# 评分与提分实证数据点（匿名化）

> 只保留相对提升、区间、方差、比例等匿名化数据点；不记录个人成绩、名次、赛道总分、attempt 标识。
> 依据类型：**实测**（第三期材料中直接记录）/ **推断**（由现象推出、无法外部确认）/ **机制**（平台规则或题面约束）。

## A. 0 分与失败

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| A1 | 0 分基本是 `evaluation_error`（评测链路失败），失败提交约占总提交 **18%** | 实测 | 0 分先判因，不要当低分 |
| A2 | 同一包在不同评测 run 中分数跨度可达 **0 / 60 / 83** | 实测 | 单次 0 分不能否定设计 |
| A3 | 某题连续 **5 次** evaluation_error，换"极限稳健版"后首次出分 56.33 | 实测 | 0 分题的最后一招是极小包 |
| A4 | 极简包出现"产出不完整"的 0 分（同题旧版 60.67 仍为最佳） | 实测 | 极简重做也要冒烟，不是必然提升 |
| A5 | 夜间失败率约 **5–10%**（正常情况下） | 实测 | 失败重提即可，不必归因到设计 |

## B. 评测方差与重 roll

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| B1 | 同题不同 attempt 分差常见 **8–15**（第三期实测 8–13） | 实测 | "多提交取最好"是主策略 |
| B2 | 同包重 roll 典型收益 **+2~+8** | 实测 | 65 分以上题的主力手段 |
| B3 | 某题同包第二次提交 **56→69（+13）**，同时升级了 CLI | 实测 | 版本升级与重 roll 叠加 |
| B4 | 高分题重 roll 也有上尾：74→75、69.67→71、61.67→62.33 等小步提升 | 实测 | 高分题不必放弃 |
| B5 | 同一包一次尝试得分 83、另一次 0（同题不同提交） | 实测 | 高方差下"取最好"而不是"求稳" |

|---|---|---|---|

## E. 融合重写（失败结论）

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|

| E2 | 融合典型结果：-8.3、-3.3、-4.7、持平、个别 0 或 evaluation_error | 实测 | 失败代价是掉分或 0 |

## F. 包体与失败率

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| F1 | 主脚本 **>30KB** 或文件数 **>8** 时，评测失败概率显著升高 | 实测反馈 + 推断 | 包体红线 |
| F2 | 文件数 27+ / 240KB+ 的"完整版"掉分最狠 | 实测 | 极简优先 |
| F3 | 实际有效包多在 **4–11 文件、60–170KB**，SKILL.md 9–19KB | 实测 | 目标区间 |
| F4 | 主脚本 65KB 的包（某图形题 v3）未见收益，后续被极简版替代 | 实测 | 大脚本不是竞争力 |

## G. 评测标准漂移

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| G1 | 某天约 11:00 之后创建的提交，多题不同题型都拿到 83 分档，较此前同质量包 **+15~20** | 实测 | 发现集体抬档就全量重提 |
| G2 | 抬档后旧包不动、只重提即可吃到 | 实测 | 不要重做包 |
| G3 | 无法从外部确认口径变化的官方说明 | 推断 | 保持"可随时重提"状态 |

## H. 队列与节奏

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| H1 | 首日排队 600+，出分 2–4 小时；出分延迟 3 小时属正常 | 实测 | 不要把 pending 当失败 |

## I. 门槛与名次规则（不含个人数据）

| # | 数据点 | 依据 | 用法 |
|---|---|---|---|
| I1 | 赛道总分 = 该赛道各主赛题得分之和；空题 = 0 分 | 机制 | 先全量覆盖 |

| I4 | 自己涨分时门槛常同步上涨（中游密集） | 实测 + 推断 | 安全垫 15–25 分 |
| I5 | 竞争后期参与人数增加（赛道参与人数从十余增到二十余） | 实测 | 后程门槛仍会同涨 |

## 使用说明

1. 引用数据点时带上编号（如 B2），便于回溯。
2. 与本轮实际观察矛盾时，以本轮为准，并更新本表。
3. 不要把本表当"分数预测模型"：方差与漂移会主导短期结果。
