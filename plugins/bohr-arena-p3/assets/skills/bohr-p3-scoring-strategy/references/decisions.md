# 决策树与检查表

## 一、主决策树（输入：单题当前最佳分 + 题型 + 包状态）

```
① 分数为 0
├─ 是否 evaluation_error？否 ─→ 视为质量低分，走 ②
└─ 是
   ├─ 同包是否曾有高分？是 ─→ 同包重提 2 条（高方差），不改包
   └─ 否
      ├─ 包是否极小（≤4 文件/≤30KB）？否 ─→ 极简 agent-first 重做
      └─ 是 ─→ 换 model/harness 元数据试 1 次
                ├─ 出分 ─→ 正常进入 ②
                └─ 仍 0 ─→ 保 1 个候选降频；把预算移给其他题

② 分数 1–45
├─ 包是否明显"脚本抽取式作答"？是 ─→ 极简重做（Agent 主答）
└─ 否 ─→ 先补必做对象覆盖（清单/工作稿字段），再重 roll

③ 分数 45–65
├─ 幻灯片/阅读/写作 ─→ patch（补金标准/diff/版本/日志/自检）→ 冒烟 → 提交
└─ 图形 ─→ 质量强化 v3（实体/关系数量、真实导出、content_map、断言）→ 冒烟 → 提交

④ 分数 65–78 ─→ 同包重 roll 2–4 条（不回改包）；每轮看方差再追加

⑤ 分数 78+ ─→ 低频重 roll（每 6–8 小时 1–2 条）；只保分不改包

⑥ 全局信号：发现"同一批包集体多拿 15–20" ─→ 全量重提最佳包（最高优先级）
```

## 二、提分手段 × 题型矩阵

| 手段 | reading | writing | graphics | slides |
|---|---|---|---|---|
| 同包重 roll | 主力 | 主力 | 主力 | 主力 |
| 全量重提（标准漂移） | 适用 | 适用 | 适用 | 适用 |
| 极简 agent-first 重做 | 0 分/低分首选 | 0 分/低分首选 | 可（曾 0→69.67） | 可（曾 0→71.67） |
| patch 增补 | 有效（+2~+7） | 有效（+2~+7） | **不适用**（多掉分） | **首选**（+19~21） |
| 质量强化 v3 | 不适用 | 不适用 | 适用（拉图上质量） | 不适用 |
| 融合重写 | 不用 | 不用 | 不用 | 不用 |
| 换元数据重试 | 0 分题 | 0 分题 | 0 分题 | 0 分题 |

## 三、单题动作前的六个问题（按顺序问）

1. **分是怎么来的**：是链路 0 分、真实低分，还是一次方差？
2. **包是哪个版本**：当前最佳包是否可用（文件在、trace 有效、CLI 最新）？
3. **pending 有几个**：≥2 个就先等出分，避免同题堵塞。
4. **题型适配吗**：图形题不用 patch；模板题不用融合；阅读/写作优先极简。
5. **有没有回滚位**：改包前是否已归档最佳包。
6. **期望与止损**：本次动作预期 +2~+8（重 roll）/ +5~+21（patch）/ 大幅跳（重做）；两次不达预期就换手段。

## 四、赛程时间表与门槛检查

| 时间 | 主任务 | 门槛检查 | 停止条件 |
|---|---|---|---|
| 前 2 天 | 33/33 全量提交 + 首轮判因 | 是否有空题 | 无 |
| 第 3 天 | 极简重做推广 + 首次 patch 验证 | 门槛是否开始上涨 | 单题 pending ≥2 即暂停该题 |
| 第 4 天 | patch 推广（排除图形）+ 集中重 roll | 与门槛差距（目标 +15~25 安全垫） | 队列 >18h 时降频 |
| 第 5 天 | 质量强化（短板赛道）+ 重 roll | 安全垫是否 ≥10 | 不再新增方案类型 |
| 第 6 天 | 冻结包结构；只重提最佳包 | 安全垫是否 ≥15 | 改包一律不批 |
| 第 7 天 | 上午收分；截止前 2–3 小时停投 | 最终确认 | 到点停止 |

## 五、门槛与安全垫检查表

- [ ] 已知每条赛道的晋级门槛与当前差距（用差值，不看名次）。
- [ ] 安全垫目标：≥15 分；低于 10 分进入"冲刺模式"（集中重 roll + 弱项 patch）。
- [ ] 若 1.5 小时内门槛涨幅 >20 分：判定为加速期，优先提"平均分最低的 2–3 题"。
- [ ] 不把"现在刚好踩线"当安全：同分先达到者靠前，晚提交有隐性劣势。
- [ ] 最后 48 小时不再改包（改包的收益 < 未出分风险）。

## 六、提交节奏检查表（每轮 2 小时循环）

- [ ] 扫一遍每题最佳分与 pending 数。
- [ ] 选 4–6 个动作：重 roll 为主，patch/重做为辅。
- [ ] 单题 pending 不超过 3；超过则本轮跳过。
- [ ] 提交顺序：先补差距最大的题，再补"上限高"的题。
- [ ] 记录：动作、时间、包版本、期望、下次检查点。
- [ ] 若发现集体抬档 → 本轮改为全量重提。

## 七、止损规则

| 情形 | 止损动作 |
|---|---|
| 同一新包连续 2 次低于原最佳 | 回滚到原最佳包，停止该方向 |
| patch 在同类题连续 2 次掉分 | 该类题不再 patch |
| 融合重写 1 次失败 | 直接放弃（历史 0/10） |
| 某题连续 5 次 evaluation_error（含极小包） | 降频到"只保 1 个候选"，预算移走 |
| 队列出分时间 >24h | 停止新增提交，只等分；下一轮改轻量 |
| 截止前 2 小时 | 停止一切提交 |

## 八、决策记录模板

```
[时间] 题号/赛道 | 当前最佳分 | 题型 | 动作（重 roll/patch/重做/不动）
| 依据（证据编号，如 B2/D1） | 包版本 | 期望 | 结果（待回填） | 是否改变后续策略
```

记录后每轮复盘一次：哪些动作命中期望、哪些手段在哪些题型上失效，用来更新 `evidence-log.md`。
