# FMT 三题全景：科学数据格式解析工程

## 用途与触发时机

在以下场景加载本技能：

- 复盘「大科学装置专项赛」的格式解析板块（三题同构），需要一份结论性全景。
- 准备复刻「为一批科研文件格式批量产出可验收适配器包」的竞赛或内部评测。
- 需要在开局尽快判断这类题的分数结构、最大杠杆、投入产出与收手点。

本技能只给全景与结论。生成器/加固/验收细节分别见 `sf-fmt-adapter-engineering` 与 `sf-fmt-local-judge`。

## 赛题结构

三题的底层任务完全相同，只按学科领域切分格式清单：

> 为尽可能多的文件格式各交一个**适配器包**：把该格式文件读成数组与带单位的元数据（`parser.py`），外加一张知识卡（`knowledge.json`），按公开样本与隐藏样本判分；做几种交几种，没交的格式记 0 分、不扣分。

| 交付文件 | 作用 |
|---|---|
| `manifest.json` | 格式身份（`format_id`/`domain`/`extensions`）、输入形态、可视化与分块声明 |
| `parser.py` | 内容签名校验 + 载荷恢复，返回数组与元数据；只能用 Python 标准库与 numpy（或白名单库薄封装） |
| `knowledge.json` | 知识卡：任务用例、元数据 schema、判型与质检规则、特征方案 |
| `expected/<样本组>.json` | 每个公开样本组一份，用 `parser.py` 真跑后回写 |

评价目标分两翼（题面规则）：**AI-ready**（能读、稳健、可分块、可提特征）与 **human-ready**（每维有名字和单位、字段齐全、可出图、有知识卡）。二者分别对应 L0/L2/Z/F 与 L1/L3/K。

## 三题结构一览

| 题 | 格式数 | 域分布 | 难度分布（1/2/3/5 分） | 难度和 | 归一分母 | 最终得分（实测） |
|---|---:|---|---|---:|---:|---:|
| 谱学、衍射与分析化学 | 102 | 核磁与质谱 29、光谱 26、衍射与表面分析 24、晶体学 21、吸附 2 | 30 / 47 / 20 / 5 | 209 | 397.1 | 94.84 |
| 计算化学与仿真 | 118 | 分子 40、量子化学 37、有限元与流体仿真 27、CAD 与工程 14 | 42 / 69 / 6 / 1 | 203 | 385.7 | 95.07 |
| 显微与成像 | 91 | 显微 51、医学影像 22、图像 18 | 27 / 50 / 14 / 0 | 169 | 321.1 | 92.37 |

- 难度分每题固定为 1/2/3/5，越难权重越高；大量格式集中在难度 1–2，少数 3–5 分格式决定高分段。
- 三题独立计分、互不影响；同一套工程方法可同时覆盖三题（实测：311 个包共用一套生成器与加固流水线）。

## 单格式计分模型（题面规则）

```
单格式得分 = (等级权重 + K + Z + F) × 难度分        每格式满分 = 1.9 × 难度分
本题得分   = Σ 单格式得分 ÷ (Σ难度 × 1.9) × 100     满分 100
reward     = 本题得分 ÷ 100                          平台返回的 0–1 数
```

**四个等级逐级累进**，只认从 L0 起连续通过的最高一级：

| 等级 | 要做到什么 | 权重 |
|---|---|---:|
| L0 能读 | 每个公开样本读出合规数组与元数据，且与 `expected` 一致 | 0.2 |
| L1 有意义 | 格式名一致、有识别证据、每维 axes 的 name/unit 非占位、本域 `domain_fields` 至少一个落在元数据顶层 | 0.5 |
| L2 稳健 | 隐藏样本全过、换文件名结果不变、随机字节必须抛异常、截断文件抛异常或给出合规产物 | 0.8 |
| L3 可视 | 可视化声明能从每个公开样本出图，并能按声明做多组对比 | 1.0 |

**加分项**（K/F 到 L1 才计，Z 到 L2 才计）：

| 项 | 内容 | 分值 |
|---|---|---:|
| K1 | ≥2 条任务用例，每条有评价指标与文献链接 | +0.1 |
| K2 | 声明的 required 元数据键在每个公开样本产物中实际出现（覆盖 ≥80%）且单位可归一 | +0.2 |
| K3 | 判型规则认出所有样本且不误认负例；质检规则把截断判坏、完整判好 | +0.1 |
| Z1/Z2/Z3 | 分块声明齐全 / 按声明生成 zarr 后逐元素拼回 / 块大小与物理单元对齐 | 各 +0.1 |
| F1/F2 | 特征方案齐全 / 可检索且与元数据对应 | 各 +0.1 |

题面示例（题面规则）：难度 2 的格式到 L3、K 满、Z 满、F 满 → 3.8 分；到 L3、K 满、无 Z/F → 2.8 分；到 L1、K=0.3 → 1.6 分。

推论（推断）：**等级是第一杠杆**。从 L0 提到 L1 的边际收益（+0.3×难度）已接近 K 满分（0.4×难度）；而 L2 再 +0.3×难度并解锁 Z（0.3×难度）。因此「多交格式但都停在 L0/L1」明显劣于「少交格式但打满 L2/L3/K/Z/F」。

## 三题结果与版本阶梯（实测）

| 阶段 | 计算化学与仿真 | 谱学、衍射与分析化学 | 显微与成像 |
|---|---:|---:|---:|
| 首版（生成器直出） | 73.14 | 78.85 | 76.08 |
| + L2 parser 加固 | 91.47 | 92.55 | 91.00 |
| + 4B magic / K3 弱嗅探 | 92.01 → 93.39 | — | — |
| + dir-mode（布局鲁棒） | 94.50 | 94.43 | 91.00（无变化） |
| + 规范级 parser 修复 | 95.07 | 94.84 | 92.37 |
| **最终** | **95.07** | **94.84** | **92.37** |

每步真实增益（实测，匿名化）：

- 计算化学：P0 修复 + L2/K3 补丁 +18.33；4B magic +0.54；K3 弱嗅探 +1.37；dir-mode +1.11；规范级修复 +0.57；读上限与后两批修复 +0。
- 谱学/衍射：L2 加固 +13.70；dir-mode +1.89；规范级修复 +0.40；HDF5 user block「免费彩票」+0。
- 显微/成像：L2 加固 +14.92；dir-mode +0；规范级修复三批 +0.50、+0.44、+0.44。

完整版本→分数→改动表与校准系数见 `references/version-ladder.md`。

## 三题各自的核心突破点

### 计算化学与仿真（118 格式）

- 首版最低（73.14）：P0 缺陷（域字段静态值覆盖真实 `n_points`）让 27 个格式 L0 回归，等于白丢。
- 最大杠杆是 **L2 加固 + K3 弱嗅探**：Parser 签名从长前缀放宽到短 magic、补 K3 弱规则后 +18.33。
- 后段靠 **dir-mode（+1.11）与规范级修复（+0.57）** 进入 95 区间；读上限、DCD/HDF5 后续修复均为零增益。

### 谱学、衍射与分析化学（102 格式）

- 首版（78.85）本地乐观分接近满分（公开侧全过），与平台分的差距**全部在隐藏样本**——这是本类题的典型形态（实测）。
- L2 加固 +13.70 最大；文本格式占多数（61/102），文本回退是主要保险；dir-mode 再 +1.89。
- 规范级修复 +0.40；最后一批 HDF5 user block 零增益，属零风险「彩票」。

### 显微与成像（91 格式）

- L2 加固 +14.92；但 dir-mode 完全无增益（hidden 为单文件），说明**布局类假设必须用代理验证再改**。
- 后段全靠**按格式规范修正 parser 识别**：DICOM 前导允许任意但魔数在 offset 128、Igor IBW 版本字节、TIA SER/EMI、TIFF 双字节序、JPEG 首个 marker 可为 APPn、BigTIFF 双字节序、NDPI 是 TIFF 容器——三批合计 +1.37。
- 这部分的 ROI 稳定为正但单批小（Σdiff×2.2%–6.3%），适合配额收尾阶段。

## 可复用结论（按可迁移性排序）

1. **建通用生成器，不逐格式手写**：从格式清单 + 公开样本自动推导内容签名，统一生成四件套；本赛 311 个包由同一套生成器产出（实测）。
2. **官方验收器代码随材料公开，判分口径可本地复刻**：本地改动能先量化 L0/L1/L3/K/Z/F，只有 L2 隐藏部分需代理（题面规则 + 实测）。
3. **先判断 parser 签名强度，再选加固方向**：签名宽松 → K3 hidden 是主风险；签名严格（长前缀）→ L2 hidden 是主风险。方向选反会把配额花在小杠杆上（实测）。
4. **内容签名只写格式级结构特征**：标准 magic、固定偏移标记、字节序、长度字段。绝不写 producer 名、版本号、日期、样本文件名——这些在隐藏样本上必变（实测：长前缀在 hidden 掉 L2）。
5. **隐藏样本失败模式有优先级**（实测+推断）：布局（多文件组/换扩展名）> 内容签名不匹配 > 超大或空文件 > K3 规则失配。布局问题用 dir-mode 处理、成本最低。
6. **合成 hidden 代理定方向，幅度按类别打折**：L2 类 ×40–46%、K3 类 ×32%、布局类 ×2.65–4.5%、规范级修复 ×2.2–9.5%/diff（实测校准）。
7. **提交门禁固定三步**：public 逐包 diff=0；garbage/truncated/opaque 行为不劣化；独立复核通过。三者全过才交（实测流程）。
8. **规范级修复是收尾期 ROI 最高的小改动**：只做能用格式规范/官方文档论证的放宽，且**保留原校验作 fallback**；无规范依据不改（实测）。
9. **提交纪律**：每次交全量包的单个压缩包；冻结副本；提交编号↔包 sha↔分数三方记录。一次打包/布局事故会白丢一次提交（实测教训）。
10. **合规红线**：不做「所有签名都失败仍恢复 payload」的兜底、不伪造 trace、不做验收语义外动作。成绩记录优先于边际分数（实测决策）。

## 本轮关键教训

1. **工程型题的提分节奏是「本地判分 → 单点修复 → 再提交」，不是「多交几发试试」。** 每一轮都回答一个明确问题：这个签名/规则/布局改动是否让隐藏样本通过率上升？验证不了的问题不值得占用提交。
2. **提交额度是硬约束。** 平台每题的可提交次数有限，且**每次提交都会重判全部包**（不是增量）。因此每一发都必须能改变决策：要么带来已验证的新候选，要么验证一个必须知道的机制；不要用提交做探路。
3. **正面做法（FMT 三题全程执行）**：先在本地完成全量官方判分（逐包 diff=0）、garbage/truncated/opaque 行为验证、合成 hidden 代理方向验证与独立复核，再提交。结果是**没有出现「有已验证候选但额度耗尽」的情况**——额度全部花在已被本地证据支持的版本上（实测）。这条比任何单点技巧都重要。
4. **首版可以早交，但必须本地全绿**：首版的作用是拿基线分并验证打包/提交链路，不是试探。首版若因打包事故被判 0，等于用额度买了一个与解析无关的教训（实测发生过一次）。
5. **额度分配参考**（推断）：首版 1 发拿基线；主杠杆（L2 加固、K3 规则）2–3 发；布局/规范级修复 2–3 发；最后留 1–2 发给「零回退的免费彩票」；始终保留上一版作为回滚锚点。
6. **平台状态会影响额度的有效性**：故障/排队窗口内的提交可能长时间不出分或返回无分状态。提交后先核对状态与包完整性，确认是平台问题再决定是否重交（机制与应对见 `sf-fmt-local-judge`）。

## 投入产出参考（推断，供排期）

- 以两晚有效工时计，三题从 0 建到 311 个包并打到 90+ 分；主要时间花在「判分—加固—复核」循环，而不是写解析器本身。
- 若复刻同类题，建议排期：收集材料与读契约 10%、生成器与首版 25%、L2 加固与代理验证 35%、布局/规范级修复 15%、QA 与提交纪律 15%。
- 收手判据（推断+实测）：公开侧已 0 回退、剩余候选无格式规范依据、且预期增益 < 0.2 分时停止；把剩余配额留给「零回退的免费彩票」而不是猜测性放宽。
