# 判分流水线（目录组织、脚本职责与汇总口径）

本文描述一套可复用的离线验证流水线。命名保持中性、与具体题目无关，便于迁移到同类「批量格式适配器」任务。

## 1. 目录组织

```
work/
├── materials/           # 题目材料：格式清单、格式卡、样本、官方工具包（只读）
├── packages/            # 当前候选包树（每格式一个目录）
├── packages_prev/       # 上一版包树（diff 基线）
├── reports/             # 逐包判分报告（每格式一个 JSON）
├── proxy/               # 合成 hidden 代理根（public + hidden/h1 + hidden/h2）
├── frozen/<version>/    # 冻结：完整包、成员清单、报告、包 sha
└── tools/               # 本文件描述的脚本
```

原则：`packages/` 是唯一可写的工作树；`frozen/` 只增不改；`materials/` 只读，绝不修改样本或格式卡。

## 2. 脚本职责

| 脚本 | 职责 | 关键实现点 |
|---|---|---|
| 单包自检 | 调官方 `check.py <包目录> --samples <格式样本目录>` | 本地 L2 只显示「公开部分通过」；用于抽样验证与排错 |
| 批量判分 | 对全部包并行跑单包自检（如 7–8 进程） | **每包独立临时副本**；判分前清理 `__pycache__`；失败重试 1 次；输出每包 JSON |
| 报告汇总 | 把逐包 JSON 聚合成一张总表 | 记录最高等级、L0–L3 状态、L2 失败码、K1/K2/K3、Z、F、潜在分 |
| 逐包对比 | 两版报告逐字段 diff | 不只比整体分；输出「变好/变差/不变」清单与格式级差异 |
| 成员对比 | 两个包树的成员差集 | 应恰好等于申报改动的文件类型与数量（例如只变 `parser.py`） |
| 便携 core 生成 | 复制官方 core 并打「非 Linux 沙箱」补丁 | 只改本地执行层，不改判分逻辑 |
| 合成 hidden 构造 | 生成 `public/ + hidden/h1 + hidden/h2` | 漂移必须符合格式语义（见 §4） |
| hidden 判分 | 用隐藏判分模式跑代理根 | 真正执行 L2/K3 的隐藏检查；按题目分母换算平台式分 |
| 打包检查 | 逐包结构 + 整包限额 + 题面级一致性 | 成员白名单、单包大小、manifest/knowledge schema、expected 覆盖、`__pycache__`/点文件 |
| 干净打包 | 只收白名单成员，确定性排序 | 排除字节码/点文件/样本；校验 zip ≤64 MiB、解包 ≤256 MiB、单包 ≤2 MiB |
| dry-run | 端到端打包+布局校验，不消耗提交额度 | 核对包内 zip 的 sha 与冻结件一致 |

## 3. 报告字段与汇总口径

每个格式一份报告，至少包含：

```json
{
  "highest": "L2",
  "levels": {"L0": "pass", "L1": "pass", "L2": "partial", "L3": "pass"},
  "K": {"bonus": 0.4, "K1": true, "K2": true, "K3": true},
  "Z": {"bonus": 0.3, "counted": true},
  "F": {"bonus": 0.2},
  "L2checks": [{"code": "...", "sample": "...", "detail": "..."}],
  "platform_error": false
}
```

汇总时算三种口径（用题目分母 D = Σ难度 × 1.9）：

| 口径 | 公式 | 含义 |
|---|---|---|
| 保守 U1 | Σ(0.5 + K1K2 + F) × 难度 | 假设 L2 全不过（停 L1、Z 不计） |
| 中位 U2 | Σ(0.8 + K1K2 + F + Z) × 难度 | 假设 L2 过但 L3 不计 |
| 乐观 U3 | Σ(1.0 + K1K2 + F + Z) × 难度 | 假设 L2/L3 全过 |

平台式分 = 单位合计 ÷ D × 100。

### 用平台分反推隐藏通过率

平台只回一个整题分 s，可换算单位 u = s × D / 100，则 L2 的隐藏综合通过率粗估：

```
p ≈ (u − U1) / (U3 − U1)
```

决策用法（实测有效）：

- `p ≥ 0.7`：L2 通过率高，剩余可提分项主要是 K3 与少量签名风险 → 做小步加固。
- `0.3 ≤ p < 0.7`：两线并行 → 先修本地已知失败，再按签名强度做定向加固。
- `p < 0.3`：L2 大面积失败 → 优先查 parser 签名（是否写死 producer/长前缀）与输入布局，K3 降优先级。

注意该式是「单位加权」比例，且 K3/Z 在隐藏样本上也可能掉，所以 p 会略高估；用它选方向而不是算精确值。

## 4. 合成 hidden 代理的构造与判分

### 4.1 构造

```
proxy/<包目录名>/
├── card.json
├── public/<组>/...      # 真实公开样本（硬链接）
└── hidden/
    ├── h1/...           # 最小公开组逐字节副本
    └── h2/...           # anchor 文件的合法漂移版
```

- 选 anchor：优先用官方样本接口对「该包 manifest」解析出的主文件，不要自己猜文件名。
- h1 用途：若 h1 都失败，说明是判分链路/布局问题，不是解析器问题。
- h2 漂移规则：
  - 整文件可解码为文本 → XML encoding 归一为 UTF-8，或在开头加一行 producer banner；
  - 二进制/固定头容器 → 只改头部 4–8 字节的版本/日期/校验和字段；**不得**前置文本 banner、不得改 magic 区。

### 4.2 负例与垃圾数据

- 代理只负责「合法变体」；K3 的负例集合、garbage（4096 字节确定性随机）、truncated（半截断）由官方判分自带的变异负责，不要自己重造一套。
- 单独压力测试垃圾拒绝：把 anchor 替换为判分同款确定性随机字节后跑隐藏判分模式，要求所有包仍抛异常（否则 `garbage_accepted`）。
- 三类行为一起回归：合法漂移通过、随机数据拒绝、截断抛异常或给出合规产物。

### 4.3 判分与报告

- 用隐藏判分模式跑（真正执行隐藏组检查），得到每格式 L2/K3 hidden 状态。
- 平台式分 = Σ(等级权重+K+Z+F)×难度 ÷ D × 100；与 base/candidate 两棵树对比。
- 报告必须含：`base → candidate（+delta）`、变好/变差格式数、残余失败格式清单 + 人工复核结论。
- 残余失败要逐个人工看：曾出现 9 个「失败」全部是构造假象（对“长 ASCII 头 + 二进制体”的容器前置了 banner、或把版本字节改进了 magic 区），复核后真实风险为 0。

### 4.4 边界

- 代理分用于相对比较，绝对分不可直接对平台分（漂移强度不同）。
- 布局类（多文件/换扩展名/嵌套目录）不在「内容漂移」代理覆盖范围内，要单独造压力集（每 hidden 组放多个同扩展名文件、换扩展名、嵌套一层目录）。
- 报代理分时同时报「折扣后预期」：L2 类 ×40–46%、K3 类 ×32%、布局类按受影响格式权重、规范修复 ×2.2%–9.5%/diff。

## 5. 冻结与对账

每个准备提交的版本：

1. 完整包树复制进 `frozen/<version>/packages/`。
2. 生成成员清单（相对路径 + 大小 + sha）。
3. 打干净 zip，记录 zip 的 sha 与条目数、解包大小。
4. 全量判分报告与逐包 diff 一起归档。
5. 提交后记录「提交编号 ↔ 包 sha ↔ 分数」；出分后先核对状态与包 sha，再写结论。

回滚：直接取 `frozen/<version>/` 重打 zip；不要从 `packages/` 当前状态重新打包（可能混入后续改动或字节码）。

## 6. 复盘指标（每轮记录一行）

| 字段 | 例 |
|---|---|
| 改动类型 | L2 加固 / K3 规则 / dir-mode / 读上限 / 规范级 |
| 影响格式数 | 文本回退 56、二进制缩前缀 37 |
| 代理增益 | +35.46（hidden 代理分） |
| 真实增益 | +13.70 |
| 校准比 | 39% |
| 回归 | 0 格式变差（public 逐包 diff=0） |

这张表是下一轮排期的依据：优先重复校准比高且回归为零的改动类型。
