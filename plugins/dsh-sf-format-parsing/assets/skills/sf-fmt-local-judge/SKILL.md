# 离线验证体系：本地判分、隐藏代理与 QA

## 用途与何时使用

- 需要在提交前知道「这一版比上一版到底好了还是坏了」，而平台只回一个整题分、且每次重新判全部包。
- 需要估计隐藏样本上的表现（L2/K3/Z 的隐藏部分无法用公开样本直接判）。
- 需要一套可以反复执行的打包、冻结、提交前检查清单，避免「打包事故白丢一次提交」。

本技能假设已有适配器包（生成方法见 `sf-fmt-adapter-engineering`）。核心结论：**官方验收器与本地判分同源，可复刻；隐藏部分用合成 hidden 代理定方向、按机制折扣估幅度。**

## 官方验收器与本地复刻

材料包自带验收器核心（`core/`）与单包自检脚本，与平台判分使用同一份代码。要点：

1. **先读 core 再写包**：判据（等级权重、K/Z/F 阈值、garbage 字节数、axes 约束、domain_fields any_of）都在 core 里可读，本地可精确复现，不必猜。
2. **单包自检**：`check.py <包目录> --samples <该格式样本目录>`，输出 L0/L1/L2/L3 状态与 K/Z/F 明细。本地 L2 最高只显示「公开部分通过」（隐藏样本只在平台/组织方判分服务上跑）；L0/L1/L3/K/Z/F 本地可判。
3. **全量批量判分**：写一个脚本对全部包并行跑 `check.py`（如 7 进程），每包**独立临时副本**，汇总每格式最高等级、K、Z、F、失败码与潜在分。
4. **本地报告口径修正**：目录型格式的 K3 本地可能高估（本地按 manifest 扩展名挑主文件，官方按样本组锚点），影响通常 <0.1 分；其余字段可靠。

### 本地判分的前置补丁（仅本地，不改平台语义）

- 验收器沙箱层用了 Linux-only 的 `resource` 模块（设 rlimit）。在非 Linux 上直接跑，每个包会报 `ModuleNotFoundError: No module named 'resource'`——这是**本地环境限制，不是包缺陷**。
- 补丁两处：非 Linux 时 `limited()` 不加 rlimit（返回 `[argv[0], "-X", "utf8", *argv[1:]]`）；`scorer_env()` 追加 `PYTHONUTF8=1`。另需给自检脚本加一个「本地无沙箱」开关（如 `--network unisolated-dev`）。
- 编码坑：控制台设 `PYTHONUTF8=1`；自检脚本在 Windows 写出的 JSON 可能用系统编码（GBK），读取时按 utf-8 → gbk 回退。
- 补丁只改本地执行层，判分逻辑与平台一致；正式提交的包不含任何补丁文件。

## 判分流水线（标准流程）

```
包树 ──单包自检（抽样）──► 全量批量判分 ──► 逐包报告聚合（最高等级/K/Z/F/潜在分）
                                          │
上一版报告 ─────────────────────────────► 逐包 diff（0 回退是硬门槛）
                                          │
合成 hidden 代理 ──► hidden 判分 ──► 代理分（仅 before/after 相对比较）
                                          │
打包检查（结构/成员/大小）──► 干净 zip ──► dry-run ──► 冻结 + 记录 ──► 提交
```

要点：

- 判分前清理 `__pycache__`；每个包用独立临时副本，否则 import 产生的字节码会让后续判分报「多余成员」。
- 逐包 diff 必须比对全部字段：最高等级、各等级状态、L2 失败码、K1/K2/K3、Z1–Z3、F1/F2、潜在分。只看整体分相等会漏掉「A 格式升、B 格式降」的相互抵消。
- 改动规模用「成员差集」核对：应恰好是预期改动的文件类型（如只变 `parser.py`），且数量与申报一致。

## 合成 hidden 代理

目的：在本地复现「隐藏样本」的两类主要风险——内容漂移与编码/版本变化，从而在提交前比较两个版本的 L2/K3 隐藏表现。

### 结构

按格式复制真实样本布局，构造一个可被隐藏判分模式读取的根：

```
<synthetic_root>/<包目录名>/
├── card.json                  # 真实样本卡
├── public/<组>/...            # 真实公开样本组（硬链接即可）
└── hidden/
    ├── h1/...                 # 最小公开组的逐字节副本（应当总是通过：验证隐藏判分链路）
    └── h2/...                 # 只改动 anchor 文件的合法变体（内容漂移）
```

- `h1` 的作用是分离「判分链路/布局问题」与「解析器问题」：h1 都过不了，说明是链路或布局错，不是解析器。
- `h2` 是核心：只改**锚点文件**，且改动必须符合格式语义。

### 漂移规则（关键，别造非法变体）

| 文件类型 | 允许的漂移 | 禁止的漂移 |
|---|---|---|
| 文本（整文件可解码） | XML 声明的 encoding 改为 UTF-8；在开头加一行 producer banner；换行符/空白变化 | 破坏必须的头部结构 |
| 二进制 / 固定头容器 | 只改头部 4–8 字节的版本/日期/校验和字段 | 在文件头前面加文本 banner；把版本字节改到 magic 区（那已经不是该格式） |

- 负例与垃圾数据拒绝不必在代理里重造：官方判分自带 K3 负例集合与 garbage（4096 字节确定性随机）变异；代理只负责「合法变体的隐藏样本」，两者互补。若要单独压力测试垃圾拒绝，用判分同款随机数据替换 anchor 后跑隐藏判分模式，确认全部包仍抛异常。

两类错误都会制造「假失败」：曾出现过 9 个格式的残余失败全部是构造假象（给 AmiraMesh/EDF/JPEG2000/CBF 等「长 ASCII 头 + 二进制体」前置了 banner），人工复核后真实风险为 0。**报代理分时必须同时列出残余失败格式并逐个人工复核。**

### 使用与解读

- 用隐藏判分模式跑：`h1`+`h2` 都进入 L2 的实际检查（隐藏组、K3 hidden）。
- 用题目分母 Σ难度×1.9 换算成「平台式分」，便于和真实分放在同一量纲下比较。
- **代理分只做 before/after 相对比较，绝不当绝对分**：漂移强度往往比真实隐藏更苛刻，绝对分会偏低或偏高。
- 报告格式建议：`base → candidate（+delta）`、`n 个格式变好 / n 个变差`、残余失败格式清单与复核结论。

## 代理分 → 平台分校准

实测校准（同一机制跨三题）：

| 机制 | 代理增益 | 真实增益 | 折扣 |
|---|---:|---:|---:|
| L2 parser 加固 | +32～+35 | +13.7～+14.9 | ×39%～46% |
| K3 弱嗅探 | +4.25 | +1.37 | ×32% |
| dir-mode | 压力代理 +41～+42（多文件场景） | +0～+1.89 | 按受影响格式权重 0%～4.5% |
| 规范级修复 | 逐批变体 partial→pass | 每批 0～+0.57 | ×2.2%～9.5%/diff |
| 读上限 | 内存/时间大幅改善 | 0 | — |

使用规则：

1. 方向可信：代理显示「0 个变差」的改动，真实侧通常不回退（前提是 public 逐包 diff=0）。
2. 幅度打折：用机制对应的折扣率给预期区间，取区间下沿做决策。
3. 布局类机制要先判断 hidden 是否真是多文件：如果代理里 dir-mode 收益巨大但另一题实测 0，说明该题 hidden 是单文件——这是结构性证据，不要照搬。

## 每步验证门槛（缺一不可）

1. **public 逐包 diff=0**：全量官方判分与上一版逐字段对比，0 个格式变差（允许变好）。
2. **garbage/truncated/opaque 不劣化**：随机字节仍被拒；截断行为仍是「抛异常或合规产物」；乱序名重跑产出不变。
3. **独立复核**：由另一个 Agent 从冻结包复算（成员集合、内容差集、逐包分数），确认「验证过的包 = 要提交的包」。
4. **免费彩票的判定**：零增益但零回退的改动（如规范允许但 hidden 未命中的放宽）可作最后一发，但必须先完成 1–3。

## 打包与提交前 QA

### 硬限制（违反即整包/整份退回）

| 层级 | 限制 |
|---|---|
| 单包 | ≤2 MiB（不含样本）；代码文件合计 ≤1 MiB；成员 ≤128；可见 helper ≤15 个且与 `parser.py` 同目录 |
| 包内禁止 | 样本/二进制文件、子目录里的代码、符号链接、`__pycache__`、`*.pyc`、点开头文件 |
| 整包 | `adapters.zip` ≤64 MiB；解压后 ≤256 MiB |
| 布局 | 顶层平铺各格式目录，或外面只多套一层目录；不能深层嵌套 |
| 知识卡 | 缺 `knowledge.json` 或 schema 不合规 → 在运行任何代码前整包退回 |

### 检查项（建议脚本化）

- 包级：成员白名单、单包大小、manifest 必填字段、`route` 与 `requirements` 合法、`knowledge` schema、helper 数量、expected 覆盖全部公开样本组。
- 题面级：`format_id`/`domain`/`extensions` 与样本卡一致（不是与清单文件一致）；`unregistered:xxx` 用冒号原编号；目录名用双下划线形式。
- 压缩包级：大小/解压上限、顶层识别、无符号链接、无点文件/字节码。
- 提交前：端到端 dry-run（打包 + 布局校验，不消耗提交额度），核对包内 `adapters.zip` 的 sha 与冻结件逐字节一致。

### 提交纪律

- 每次提交只放**一个** `adapters.zip`，输出目录不要有其它候选包（多文件曾导致整份 0 分，白丢一次提交）。
- 全部包一起交：每次只按当次压缩包判分，漏掉的格式记 0。
- **提交前必须本地官方判分全量通过**（逐包 diff=0 + garbage/truncated/opaque 显式验证）；**不要在未验证时消耗额度**——每次提交都会重判全部包，且次数有限，拿额度做探路等于把决定权交给运气。
- **单包冻结**：每个准备提交的版本先冻结（完整包 + 成员清单 + 包 sha），提交内容与冻结核对无误后才交；回滚时按冻结包重打，不从被改动过的工作目录重打。
- **版本与分数对账**：记录「提交编号 ↔ 包 sha ↔ 分数」三方映射，并在收到分数后先核对状态（已评分、分数 >0、包 sha 与冻结件一致）再更新结论；高分与未验证包对不上时，以冻结件为准。
- 配额意识：平台每题提交次数有限（本次三题各用满 10 次），把提交留给「已验证 0 回退 + 有明确预期增益」的版本；首版用于拿基线与验证链路，也必须本地全绿。

## 平台故障与出分延迟的应对

机制（实测 + 题面规则）：

- 验收是共享资源：提交可能先排队再判分（本次观察到约 1–1.5 小时的出分延迟），期间状态停在未评分属正常，不是包坏了。
- 平台侧偶发评测进程/worker 故障：表现为提交长时间无结果、或评测失败（该次不出分）。这类尝试通常**不按 0 分裁决**，平台恢复后可能自动重评并补出分数。
- 同一份内容重复提交通常得到相同分数（实测：同包重提分数完全相同）——重交不能提分，只用于修复提交链路或恢复故障期的尝试。

应对清单：

1. 提交前完成本地全量验证；提交后**先核对包完整性**（包 sha 与冻结件逐字节一致）再解读分数。
2. 收到异常状态（长时间无分、评测失败）时先区分归因：包缺陷 → 自己修后重交；平台问题 → 等自动重评，不要立即用新版本覆盖掉最优版本。
3. 保留最优冻结包：平台恢复后按原包重提即可，不需要重新生成。
4. 不要用「重交同样的包」当提分手段；也不要在故障/排队窗口消耗本可用于已验证候选的额度。
5. 把「平台故障」「自身打包/布局问题」分开记录：前者只能等，后者必须修（本次出现过一次自身输出结构问题导致 0 分，属后者）。

本轮实际情况：FMT 三题的有效提交均无评测错误，没有出现「已验证候选因平台故障无法提交」的情况；影响主要是出分延迟，以及一次自身打包事故消耗的提交（实测）。

## 失败模式与对策

| 现象 | 常见原因 | 对策 |
|---|---|---|
| 本地全部通过、平台分低 | 隐藏样本 L2/K3 失败 | 用合成 hidden 代理定位；先查签名强度 |
| 某格式平台分明显低于本地 | `input_mismatch`（布局）/`hidden_failed` | 布局类用 dir-mode；内容类按格式规范放宽识别 |
| 反复出现「L2 公开部分通过」但无法提升 | 本地看不到隐藏结果 | 不要盲改；用 h2 变体对照（改前 partial → 改后 pass）验证 |
| 打包后判分全挂 | 多余成员/`__pycache__`/布局/超限 | 用结构检查脚本逐包核对；重打干净 zip |
| 提交后 0 分 | 输出目录多文件或压缩包不可读 | 输出目录只留一个 zip；dry-run 核对包内 sha |
| 分数与包对不上 | 验证的是 A 版、交的是 B 版 | 冻结制 + 包内 sha 逐字节核对 |
| 本地 K3 与平台差 1–2 个 | 目录型格式 anchor 口径差异 | 以公开组锚点为准复核，影响 <0.1 分，不必追 |

## 自检清单

- [ ] 本地判分环境已打「非 Linux 沙箱」补丁，控制了 UTF-8 编码。
- [ ] 抽样单包自检 + 全量批量判分都跑过；逐包报告已归档。
- [ ] 与上一版逐包 diff：0 个格式变差（全部字段，不只看整题分）。
- [ ] garbage/truncated/opaque/乱序名 四类行为已显式验证。
- [ ] 合成 hidden 代理已跑；残余失败格式已人工复核并说明。
- [ ] 打包检查：逐包 OK、0 不符、0 缺 expected、整包限额 OK、无字节码/点文件。
- [ ] dry-run 通过；包内 sha 与冻结件一致。
- [ ] 提交前已完成全量本地官方判分（不是抽样）；未验证的版本没有占用提交额度。
- [ ] 本版已单包冻结，且提交内容与冻结件逐字节一致（可直接回滚）。
- [ ] 提交记录：提交编号 ↔ 包 sha ↔ 分数 三方齐全；出分后先核对状态再更新结论。
