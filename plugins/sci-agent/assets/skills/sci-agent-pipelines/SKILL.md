# 科研 Agent 流水线：批量构建与自动化

## 1. 用途

当有多类科研任务需要沉淀成多个 Agent Skill，或需要无人值守地反复运行同一类自动化流程时，用它设计流水线：**任务书 → 云端/本地构建 → 打包 → 自检 → 交付 → 回退**。

不适用：一次性脚本、单任务手工操作。

## 2. 任务书（每个任务一份，写清再动手）

```markdown
# 任务：<skill-name>
## 目标：一句话说明这个 Skill 解决什么问题
## 输入：目录/文件/契约（有哪些键、什么格式）
## 输出：产物清单与格式（文件名、格式、必须字段）
## 约束：纯标准库/离线/退出码恒 0/单文件大小上限
## 质量红线：证据必须逐字引用；缺口必须显式标注；两次运行结果一致
## 自检：给出可执行的自检命令与期望输出
```

任务书是后续所有自动检查的依据；不要边构建边改目标。

## 3. 批量构建

- 每个包独立会话/独立目录构建，避免互相污染。
- 构建产物先落到工作目录，**通过自检后才"提升"为正式包**（`pkg/` → `packages/<name>/`）。
- 并行度按资源控制：云端并发 2–3，打包与提交串行，避免互相踩。
- 超时与中断：任务书第一步先写 SKILL.md 骨架与最小可运行脚本，超时后能续跑而不是重来。

## 4. 打包白名单

只打包必要文件，禁止把临时产物带进交付包：

```text
SKILL.md            # 必需
scripts/*.py        # 实现（纯标准库）
references/*.md     # 规范/模板
```

- 排除：`__pycache__/`、`*.pyc`、`.venv/`、测试输出、会话日志、大二进制文件。
- 单文件 ≤25KB、单技能 ≤64KB、整体 ≤320KB 之类的上限要写进自检脚本。
- 压缩包用正斜杠路径（跨平台可解压），避免反斜杠导致解压失败。

## 5. 确定性自检（自动化核心）

```bash
python3 -B scripts/main.py --help                    # 退出码 0
python3 -B scripts/main.py --input demo/input --output demo/out
python3 - <<'PY'
import json, hashlib, os
r = json.load(open('demo/out/result.json'))
assert r.get('status') in ('ok','partial','insufficient_evidence')
# 关键产物存在且可解析
# 同一输入两次运行产物哈希一致（确定性）
PY
```

- 至少覆盖：正常输入、空输入、坏 JSON、缺参数。
- 产物校验：SVG 可解析、PDF `%PDF-`、Office 可打开、CSV 列数一致。
- 失败要"可解释"：日志里记录哪一步降级、为什么。

## 6. 版本与回退

- 每次交付前归档上一版（`pkg_prev_<时间>/`），任何新包都可一键回滚。
- 记录版本历史：改了什么、为什么、影响哪些产物。
- 失败恢复：上传/传输通道故障先单条探测，恢复后集中补；本地始终保留可交付快照。

## 7. 自动化守护（无人值守时）

- 定时循环：检查 → 决策 → 执行 → 记录；单轮动作数设上限。
- 防止重复：同一任务同时只允许一个构建/提交实例（文件锁）。
- 预算守卫：任何对外提交/调用前先检查剩余额度，满则跳过并记录。
- 日志：每轮写一行摘要（时间、动作、结果），便于事后复盘。

## 8. 自检清单

- [ ] 每个任务有独立任务书与自检命令。
- [ ] 打包白名单生效，无临时文件/缓存。
- [ ] 四种输入场景（正常/空/坏/缺）都返回合法产物且退出码 0。
- [ ] 同输入两次运行结果一致。
- [ ] 每版可回退；日志可追溯。

## 9. 示例（示例，非正式案例）

把"文献阅读 / 学术写作 / 科研图形 / 学术演示"四类 Skill 批量构建：同一任务书模板 + 各自的输入契约；云端 Agent 逐包构建，本地流水线负责打包白名单与自检，全部通过后统一归档；某天发现一个包渲染中文字体缺失，回滚到上一版并把它加入"无中文字体环境必测"检查项。

## 10. 边界

- 自动化不替代质量判断：自检通过 ≠ 结果正确，关键交付仍需人工抽检。
- 不把"提交/上传成功"当"任务完成"：要看到目标端的状态。
- 不在无人值守循环里做不可逆操作（删除、覆盖无备份）。
