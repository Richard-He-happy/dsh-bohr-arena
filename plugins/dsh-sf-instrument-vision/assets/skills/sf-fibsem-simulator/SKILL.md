# FIBSEM 模拟器操作打法

## 用途与何时使用

用于「在模拟器中完成仪器操作」类任务：样品台/机械手绝对定位、保护层沉积、沟槽铣削、lift-out 全流程、图像对齐。典型结构：题面给固定 scenario 初态与十道子题，答案包提供十个入口脚本；评测方为每个子题单独申请 simulator lease、注入连接信息后执行脚本，按结果准确度 A、违规 V、动作数 E 评分。也适用于其它「固定初态 + 单题独立 + 平台侧 lease 容量受限」的模拟器评测。

## 十入口结构与 B/G 分组

| 组 | 入口 | 类型 | 要点 |
|---|---|---|---|
| B01–B04 | 样品台定位 / 机械手定位 / 保护层沉积 / 矩形槽铣削 | 纯状态移动与参数化加工 | 题面把目标值与图案参数写死，是**满分锚点** |
| B05 | 十字标居中 | 图像反馈 | 采 SEM → 识别十字中心 → 移动置中 |
| G01 | 保护层 + 粗槽 + 精修 + 底切 | 全流程加工 | 55° 加工、回 0° 底切；方向与连接桥硬约束 |
| G02 | 薄片转移至铜网 | 全流程转移 | 针-薄片桥接、切残桥、送铜网、桥接、释放、撤针 |
| G03 | 薄片减薄 | 全流程加工 | 两侧各 9×1.2 µm、深 ≥8 µm；保留核心与铜网连接 |
| G04 | 针尖对齐薄片 | 对齐（无加工） | 回 T=0，只动机械手；stage 其余轴不变 |
| G05 | 携片对齐铜网 | 对齐（无加工） | 移动 stage 送铜网，薄片自由端对齐接收区 |

- 入口契约：`answers/<子题>/run.sh`，工作目录为入口自身目录，评测方以 `sh run.sh` 启动；通过 `FIBSEM_RPC_HOST`、`FIBSEM_RPC_PORT`、`FIBSEM_RPC_AUTH_TOKEN` 连接当前子题的模拟器。
- 答案包内**不得**自行申请 lease、不得夹带 token/证书/密钥；初态全部由模拟器按 scenario 提供，不需要加载场景或重做前置题。
- 共享代码放包内，路径相对入口解析；正常退出（rc=0），避免无限重试与依赖采图却无兜底的写法。

## 评分与 lease 容量（关键机制）

- 子题得分 `= 100 × A × (0.80 + 0.15V + 0.05E)`；合成分 `= Σ(子题得分)/10`。
- `A` 连续（位置/几何/图像判据），`V` 0 违规为 1、每次 −0.25，`E` 动作数 ≤ 参考+2 为 1、之后每多 1 次 −0.1；硬约束失败该题归零。
- **评测方为每个子题单独起一个 simulator lease**；能成功启动的 lease 数决定有多少子题被评到。评测按 B01→B05→G01→G05 顺序，容量不足时靠后的子题是「未被评到」而不是「答案被判 0」。
- 可近似记作 **合成分 ≈ 10 × 成功启动 lease 的子题数 × 平均质量**（质量 = A×(0.80+0.15V+0.05E) 与硬约束的乘积；满分时即每题折算 10 分）。
- 实测：合成分是 10 的整数倍 ⇒ 被评到子题全为满分（30/40/20 分别对应 3/4/2 个 lease）；出现小数 ⇒ 某子题拿到部分分（48.5702 = 4×100 + 85.70）。选做上限首先由平台容量决定，其次才是 A。
- 因此策略是：把 B01–B04 做稳做满（每发都保底 +40），把 B05 的 A 尽量提高（+8.57 上限），G 组在有真机证据前不押额度。

## 核心流程

### B01–B04：锚点入口

1. 读初态（只读状态查询不计动作步数）→ 计算目标 → 发绝对移动/加工指令 → 退出。
2. B01/B02 终态严格等于题面目标值，不改无关轴。
3. B03/B04 用题面给的图案参数与 spot 参考值（12×2×1 µm、spot 0.48；12×4×5 µm、spot 0.2），加工后保持题面要求的倾角；不需要私有标定补偿。
4. 动作数压到参考动作数内（E=1），不产生违规（V=1）。

### B05：采图 + 绝对移动

- 题面要求「采集 SEM 图像、识别十字槽中心、通过 X/Y 移动把交点置于视场中心（参考一次移动）」——显式采图步骤要做，否则 `V` 会被扣、上限只剩 85%。
- 采图参数按题面（512×512 像素、水平视场 100 µm）；采图与解码用 try/except 包裹，平台图像异常时不崩。
- 终态用绝对移动落到标定位姿，而不是依赖单帧检测的闭环误差；实测校准中心与 (0,0) 差 0.02–0.04 µm 量级，A≈0.857（V=1、E=1 反推）说明距离判据是连续分。
- 若追求 A→1：做「检测 → 绝对移动 → 再检测 → 再绝对移动」的两步闭环（推断：在 tol≈0.21 µm、A=1−d/tol 假设下自洽），动作数仍可控制在参考+2 内。

### G 组：全流程作业

- 先读题面的方向约定与硬约束：G01 要求 −Z 侧保留一个连接桥、+Z 侧开深度 ≥8 µm 沟槽、核心 10×2 µm 不被切到、底切前回 0°；G02 要求结束时薄片-基底分离、薄片-铜网连接、薄片-探针分离同时成立；G03 保留核心与铜网连接并在结束时回 T=0；G04 对齐时 stage X/Y/Z/R 不变、只动机械手；G05 只动 stage 送铜网、不做沉积/切割/桥接/释放。
- 运动语义：**探针 Z 轴正方向表示下降，抬针用负 Z 位移**；沉积/切割必须设置图案位置、尺寸、深度、方向角与 `spot_size_um`，释放切缝要覆盖连接桥整个截面。
- 仿真行为的实测限制：铣削切割不一定产生可观测的「薄片脱粘」信号（多组候选切割后薄片与基底仍同步移动）；接触焊会使探针移动被静默忽略（模拟器锁死）。因此 G02 类改动必须有 E2E 判据实验，否则不盲改。
- 方向符号（样品坐标系 vs 台坐标系）是最常见的硬约束错误来源；改动前先在真机 lease 上用「stage 移动 → 图像区域位移」检验符号。

## 几何标定与自动求解

1. **采图 + 对照目标参考图**：用官方目标 SEM/FIB 参考图做目标函数，指标用 `ncc`（相似度）与 `rms`（误差）；先测同场景重复采集的噪声本底，指标贴近本底后再优化没有意义。
2. **网格/坐标下降搜索**：stage/manip 各轴依次搜索，步长从 1 µm 收到 0.5、0.25 µm；目标用 SEM+FIB 的 combined 指标。
3. **碰撞边界**：报 `needle collides with the stage` 一类的位姿不可用；若 ±0.25–0.5 µm 试探都碰撞，说明位姿已到接触边界，应停止搜索（这正是「桥接前」的物理含义）。
4. **位移换算**：stage 平移量与图像像素位移用区域互相关标定比例（实测 stage 移动 6 µm ↔ 约 51 px），可用来判断薄片是否随基底移动；需要亚像素时可用相位相关法（推断，未在本题平台验证）。
5. **自动求解的产物是常量位姿 + 最少动作**：把搜索脚本、候选位姿、指标表留档，便于回滚；图像最优 ≠ 平台判据，若平台分与图像指标矛盾，优先做「物理共面/隐藏 3D 位姿」对照假设，而不是继续微调图像。
6. **参考解取证**：拿相邻子题的初态/目标态做差分，可定位真实残桥、切痕等几何线索；但投影角度换算与 E2E 验证缺一不可，否则只是「盲改」。

## 真机 E2E + mock 验证

- **真机 E2E**：用公开接口申请 lease → 注入环境变量 → 以入口目录为 cwd 执行 `sh run.sh` → 检查 rc、动作数、终态状态、采图指标 → 显式释放 lease。每个改动都要有 E2E 记录。
- **mock**：本地假 RPC 服务跑十个入口，检查参数与调用次数（如 B05 应为 1 张图 + 2 个移动动作，G04/G05 为 2 个动作），保证不会因消息格式/顺序错误超时。
- **静态检查**：`sh -n` 十个入口、`py_compile` 通过、纯标准库、无 pycache、路径相对自身解析、无凭据、不申请 lease。

## 提交窗口与最后一发

- 先交锚点版本（B01–B04 + 最小改动的 B05），确认平台能出真实分；再交单变量改动（一次只改一个入口或一组常量）。
- **故障判别（实测）**：真实评测 20–25 分钟；2–9 分钟的快速失败 + 0 分 ⇒ 评测侧 lease 不可用，不是答案问题。同内容包一次 40 一次 0 是平台故障的决定性证据。
- 平台按历史最高分保留，无下行；同内容重交只在「抽 lease 容量」有意义时使用，不用它做内容验证。
- **最后一发决策树**：
  - 新改动有真机 E2E + 指标证据 → 交新内容；
  - 只有静态证据、没有 E2E → 不交，保留额度给「容量抽签」或更稳内容；
  - 平台故障窗口 → 等恢复信号（lease 探测成功、公开提交正常出分）再交；窗口结束前必须用掉。
- 恢复信号：公开提交能正常出分、lease acquire/release 连续成功、失败窗口过去后再提交。
- 本轮实测：前期有 5 发落在评测服务/租约故障窗口，评测没真正执行、未拿到有效分却消耗了额度；等评测恢复、内容收敛时可用额度已所剩无几。**10 发要当预算，最后 2 小时至少留 2 发。**

## 失败模式与对策

| 现象 | 可能原因 | 对策 |
|---|---|---|
| 整份 0 分但同内容曾高分 | 评测侧 lease 容量/故障 | 看评测时长与同包对照；不要回滚已验证内容 |
| G 题全 0 | 容量不足从未被评到 | 优先保证前段入口；G 组不作为额度投放重点 |
| 某入口 0 分 | 入口报错/超时/硬约束失败 | 真机 E2E + rc/动作数/终态检查；硬约束逐条对照题面 |
| 采图/解码崩 | 平台图像格式与本地不同 | 采图与解码 try/except，终态不依赖图像 |
| 焊后移动被忽略 | 接触焊使模拟器锁死 | 不做接触焊；保持悬浮高度操作 |
| 铣削后薄片未脱离 | 模拟器不体现脱粘动力学 | 先做「stage 移动 → 薄片是否随基底同步」判据实验 |
| 动作超参考导致 E 降分 | 动作序列啰嗦 | 压到参考动作数内；不采无关图 |
| 额度落在评测故障窗口 | 未先确认平台健康 | 先看公开出分/lease 探测；故障窗口不提交 |
| 内容收敛时额度已所剩无几 | 前期提交没有预算 | 锚点先交、单变量其次；最后 2 小时留 ≥2 发 |
| 同内容重交抽签消耗额度 | 把额度当抽奖 | 只在内容已收敛且只剩容量变量时重交 |

## 自检清单

- [ ] 十个入口 `sh -n` 与 `py_compile` 通过、路径相对自身解析？
- [ ] 只用注入的 RPC 环境变量连接，不自申 lease、不带凭据？
- [ ] B01–B04 的终态/参数/动作数与题面一致（锚点不动摇）？
- [ ] B05 是否显式采图 + 绝对移动，并带异常兜底？
- [ ] 每个改动是否有真机 E2E rc=0 + 指标对照？
- [ ] 是否理解当前分数 = 10×lease 数 + 部分分，并据此安排提交？
- [ ] 最后一发是否为已验证内容，且留在窗口后段？
- [ ] 是否按「锚点 + 单变量 + 组合 + 预留」分配 10 发，最后 2 小时留 ≥2 发？
- [ ] 故障窗口（快速失败/lease 不可用）是否坚持不提交？
- [ ] 最后一发是否只交已验证最优内容（不是未验证改动或纯抽签）？
