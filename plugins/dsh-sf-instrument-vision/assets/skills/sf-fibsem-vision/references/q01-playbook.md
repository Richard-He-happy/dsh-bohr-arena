# Q01 执行手册（四子任务组合视觉题）

## 0. 拿到资源后的第一小时

1. 通读题面。题面里会点明「资源包个别旧文件与新规则不一致时以题面为准」，不要照旧文件做。
2. 取资源后校验哈希、解包、补读权限（包内文件可能只有所有者可读，容器内进程读不到）。
3. 只用大题层的组装工具（`make_submission.py`），不要用各模板目录里的同名脚本——它们写的是另一种题的输出格式。
4. 先用官方组装工具跑通一份最少交付，确认 `--check` 输出 READY 并记录 fingerprint 与查分方式。
5. 建四个独立候选目录（每道小题一个），冻结基线四件套，之后每次只替换一个文件。

## 1. 小题一：八类分割

### 1.1 先拿基线

- 模板 + 运行时权重注入 → 打免构建包；官方自测必须出现 `SELF-TEST PASSED`，否则按 `[FAIL]` 原因码排查。
- 隐藏参考分：模板路线 40.84；验证集 54.72（逐类可复现）。

### 1.2 推理侧增强（优先）

- 翻转 TTA：对输入与提示做镜像，SAM 概率镜像平均（DINOv3 仍只跑 1 次，SAM 前向 1→3 次）；耗时仍远低于时限。
- 按类后处理配置：`source`（sam/coarse/mix/tta/tta_mix/avg/max）、`threshold`、`min_area`、`max_area`、形态学、`keep_largest`，写入包内 JSON。
- 选择准则：只在「两个采集会话都提升」的类上采用改动，否则保留官方 calibration。
- 实测：h/v 翻转 TTA + 稳健后处理 = 隐藏 40.836→42.8966（+2.06）。

### 1.3 不要重训（负面结论）

- 40 张真实图 + 用验证集选模型 ⇒ 隐藏集崩盘（验证 60.6 / 隐藏约 15–23）。公开训练 40 张只来自 2 个采集会话，无法支撑跨会话泛化。
- 必须重训时的前置条件：先按采集会话做 train/val 划分，用「一会话训、另一会话验」再对调；worst-session 与整体分差距大就别上线。
- 本地 20 张验证上的阈值搜索在会话留出/半图留出协议下多为负增益（详见 `experiment-log.md`），这正是「验证涨、隐藏跌」的机制。

### 1.4 提交前检查

- 每个 `.npy` 形状 `(8,H,W)`、uint8、仅 0/1、尺寸等于原图、逐样本齐全；单张异常写全 0 且不让程序崩。
- 代码包顶层有 `predict.py`，无 pycache/不可见文件；入口按 `--input`/`--output` 参数定位目录。
- 先跑官方 `--check`，再自测 N 张；有条件时用候选缓存做精确重放，确认包内后处理与调参口径逐像素一致。

## 2. 小题二：零训练提示分割（ROI 最高）

### 2.1 流程

1. **复刻重放**：用官方重放程序与官方评分器在本地跑通，先复现官方示例文件的逐类验证 IoU（误差应为 0.00）。
2. **候选缓存**：对公开 60 张逐图 dump 每条短语与负样本的实例掩膜和分数，落盘缓存；后续规则搜索只读缓存，不再跑模型。
3. **逐类规则搜索**：枚举 `threshold`、`select`、`negatives`、`min_area`、`keep_largest`，用与官方一致的排序口径算逐类 IoU 与宏平均。
4. **跨会话交叉验证**：把公开训练 40 张按采集会话分两组，A 调参 / B 验证再对调；重点类规则必须在两个独立会话都为正才冻结。
5. **冻结与提交**：只改 `prompt-seg.json` 一个文件；过契约 check；按每日 3 次上限安排顺序（先验方向、再加类、最后交最优）。

### 2.2 规则阈值表（示例形态，类名按题面）

| 类 | 短语概念 | threshold | select | 后处理 | 验证行为 |
|---|---|---:|---|---|---|
| 保护层 | bright long rectangle | 0.50 | largest | negatives | 15.31→37.71 |
| 标记 | plus sign | 0.80 | none | — | 41.60→71.81 |
| 样品 | rectangular block | 0.50 | largest | min_area 1000 | 4.50→25.45 |
| 针 | long tapered rod | 0.40 | none | min_area 4000 + negatives | 70.42→76.50 |
| 其余四类 | 保守保留基线规则 | — | — | — | 不动 |

- 表内数字是公开验证 20 张的逐类 IoU；四个重点类在独立采集会话上同向为正，才作为迁移依据。
- `select: largest` 在过分割候选上会把单类 IoU 归零（预测 10 万像素级 vs 真值 1 万级），改 `top-1` 后多类回升；`nearest-to:<宿主类>` 适合针尖沉积这类依附结构。
- 提示词只决定候选池：同一个短语在不同会话效果不同，规则（threshold/select/negatives）比措辞更可迁移。
- 参考上限：把真值外接框直接当提示，隐藏集约 77 分——差距在「用文字告诉模型找什么」。

### 2.3 契约与拒收

- `schema` 必须 `fib-prompt-seg/v1`；`classes` 键只能是八类；`phrases` 1–4 条 ASCII 英文（无标点、≤160 字符、≤32 token）；`negatives` 0–4 条；`threshold` 0.10–0.90；`select` 见题面枚举；`postprocess` 只有 `keep_largest` 与 `min_area`。
- 任何按图字段（图号、文件名、坐标、点、框）都会被拒收；白名单外的键也拒收。
- 同一文件重交逐位同分；每日 3 次计分提交，同内容同日只算一次。

## 3. 小题三：针尖定位与追踪

- 零改动路线：直接引主办方示例镜像地址（参考 45.27）或打包模板代码包（45.24）；示例镜像对项目外调用方通常拉不动，但只引用地址不影响受理。
- 若自训：只能用本题针尖训练集、自生成数据与公开预训练权重；输出每 case 一个 JSON + 每帧掩码 PNG；严格逐帧因果（第 t 帧只能用 0…t 帧）。
- 输出坐标 x 向右、y 向下、左上角像素中心为 (0,0)；掩码模式 1 或 L、尺寸等于原图。
- 评分为 `0.60·Tip + 0.15·Track + 0.20·Seg + 0.05·Neg`；无针帧误报或漏报都直接影响 Neg 分量。

## 4. 小题四：AI 成对数据

### 4.1 生成流程

1. 来源分配：每张公开帧只用一次（40 训练 + 10 验证作参考图），`sources` 如实写；不得用测试图或近重复副本。
2. 每对一次真实 AI 调用：image-to-image 局部编辑即可；记录模型/版本、完整 prompt、参数、参考图；请求与响应哈希写进 trace 回执。
3. 标签安全：公开帧的八通道标签连同目标周围真实上下文（约 28 px）逐像素贴回，只有无标注背景用生成像素；改了轮廓/遮挡/针尖的必须重标，拿不准就换图（标签没有「忽略」档）。
4. 多样性：12 对额外组合稀有部件（ucut、needle、tip_deposition、grid_deposition 从其它公开帧裁出，像素与掩膜同一几何）；整帧统一成像退化（gamma/增益/黑白电平/噪声/扫描行抖动/离焦场），逐对参数进 trace。
5. 近重复门：与公开 60 张比 `d64`/`d256` 缩略图平均绝对差（同时 `d64≤3`、`d256≤4` 即拒）；逐对记录数值；被拒的换种子/强度重生。
6. 机器校验：50 对、灰度 mode L、八通道 uint8 0/1、`trace.jsonl` 每个样本有 `succeeded` 的 generate/edit 祖先、harness 文件哈希、来源在允许 ID 内、大文件在 60 MiB 内。
7. 参考分：50 对平台 41.5212（外部同类 36–40；只用真实 40 张 41.29；主办方 50 对 41.49）。同配方换种子隐藏分 34.9–46.0，小分差是噪声。

### 4.2 审计要点

- trace 里失败的调用也要记；`succeeded` 时 `outputs` 不能为空；没有唯一请求字节串时把模型、prompt、参数、参考图哈希拼成 JSON 文本取哈希。
- 不能出现凭据相关键或长串；脚本从环境变量读密钥。
- 组合/裁切/退化类操作必须登记为 `composite`/`transform`，并指向 harness 内的脚本。

## 5. 组装、检查与提交

1. 用大题组装工具把四个分项写进 `outputs/`：`--prompt` 拷提示文件、`--image` 写镜像地址、`--code` 拷代码包、数据包由数据 kit 打包生成。
2. `method.md` 按小题分节，必须有 `## Pretrained weights` 标题行并删掉占位注释；数据包的 `data-ai/method.md` 另写一份。
3. `--check` 必须 READY；每条 `problem:` 逐条修完再提交。
4. 提交时附过程记录（trace）：Agent 做题交会话记录，人工做题一行一步手写；密钥替换为占位符；先做校验再提交。
5. 出分后用查分工具看各小题分数、状态与原因码；`evaluation_error` 先等平台自动重评，不要急着重交。
6. 平台额度按实际 10 次/24h 计划；同字节文件沿用上次分项分，改哪道重评哪道。

## 6. 候选冻结与校验工具链

- 冻结脚本职责：拷基线包 → 只替换目标文件 → 跑官方 `--check` → 计算 fingerprint → 写候选目录与改动清单。
- 静态检查：zip 顶层 `predict.py`、无 pycache/隐藏文件、`py_compile` 全部通过、入口 `--input/--output` 参数可用。
- 冒烟：用验证集 1–N 张跑真实推理，检查输出形状/类型/尺寸；CPU 冒烟可验证代码路径（速度慢但能确认可运行）。
- 精确重放：用提交包自己的后处理代码在候选缓存上重算，与调参值逐像素对比。
- 提交前把「候选目录 + 改动范围 + 预期分项 + fingerprint」记进实验记录，出分后归因。

## 7. 时间与额度预算（24 小时窗口）

| 用途 | 次数 |
|---|---:|
| 基线锚点（确认受理与复现） | 1 |
| 单变量探针（TTA / 后处理 / 尺度 / prompt 规则） | 4–5 |
| 组合 | 2 |
| 预留（最后 2 小时最优版） | 2 |

- 小题二单独按每日 3 次计，不要与其它小题的额度混算。
- 不把额度用于「验证包是否有效」或纯抽奖式重交；最后一发必须是已验证的内容。
