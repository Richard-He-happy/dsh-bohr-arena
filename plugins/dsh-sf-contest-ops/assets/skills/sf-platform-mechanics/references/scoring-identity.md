# 评分恒等式与 trace 门控

## 1. 公式

```text
score = 100 × harbor_reward × trace_factor
```

- `harbor_reward`：评测器按题面 metric 计算的 0–1 原始奖励。
- `trace_factor`：trace 质量门控系数，按 trace 是否真实、完整、可读判定档位。
- 平台回执通常会给出最终 score；部分题目会给出分项/子题分，可用于反推。

## 2. trace 门控的工程口径

平台没有公开完整档位表，按保守工程口径要求自己：

| trace 质量 | 预期系数 | 要求 |
|---|---|---|
| 真实原生会话、步骤 ≥5、可完整读取 | 1.0 | 提交前 `trace validate` 必须 valid |
| 合成/过短/不可读 | 0 或严重折扣 | 绝不用合成 trace；曾出现大批评测失败或 0 分 |

做法：
1. 让真实 Agent 在**最终产物目录**里跑一遍关键步骤（读包→自检→最小修复），自然产生原生会话 JSONL。
2. 复制该会话文件作为 trace；不要裁剪、不要补写、不要改时间戳。
3. `playground trace validate --trace <file>` 输出 `valid: true` 才允许提交。
4. 记录 trace 的事件数与可用事件数，便于复盘门控异常。

## 3. 本地 scorer 校准（提交前必做）

目的：让"本地分"能预测"平台分"，否则所有本地迭代都是盲调。

校准方法（按优先级）：

1. **官方参考基线**：若题面/资源包提供参考解或模板基线，在本地复刻其 scorer，跑参考解；本地分与平台公开参考分误差应 <0.1。
2. **常数/均值基线**：构造一个平凡预测（常数、均值、朴素启发式），本地跑分与平台同类基线对齐。
3. **历史同题对分**：用同一题公开的"产物特征 → 分数"对照，确认量级与方向。
4. **一次真实探针**：用一个小而完整的候选提交一次，拿回执里的 reward 与本地分对账；误差可接受后再信任本地 scorer。

校准记录建议：

| 对照点 | 本地分 | 平台分 | 误差 | 结论 |
|---|---|---|---|---|
| 参考解 | … | … | … | scorer 复刻正确 |
| 常数基线 | … | … | … | 量级一致 |
| 首个真实候选 | … | … | … | 可用于迭代 |

## 4. 反推题分（只有总分时）

- 若题目由若干等权子题组成：`单子题分 ≈ 总分 × 子题数`；观察阶梯值（如 20/30/40/48.57）可反推"被评测到的子题数"。
- 若总分 = 各子题加权和：先用一个已知分项极值（如某子题满分/0 分）反推权重，再解其它分项。
- 反推结果只用于"下一步动哪里"，不作为对外结论；写复盘时标注为推断。

## 5. 门控异常排查

| 症状 | 可能原因 | 检查 |
|---|---|---|
| score 明显低于本地校准值 | trace 门控打折 / 分项未跑完 / 评测失败 | 看回执 reward 与 trace validate；换真实完整 trace |
| 同一内容两次分数巨差 | 评测链路/租约容量/评分器差异 | 对比评测耗时与子题分项；见 lease-mechanics |
| 分项全 0 但本地正常 | 包布局/路径/接口不被评测器识别 | 对照题面路径约定；用小包探针验证 |
