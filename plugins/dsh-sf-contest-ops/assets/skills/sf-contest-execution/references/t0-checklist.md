# T0 检查单（开赛 0–30 分钟）

## A. 状态与规则（0–10 分钟）

- [ ] 每题 `status=open`，`roundStartAt/roundEndAt` 与赛程一致。
- [ ] 拉取本轮规则：提交上限、额外约束、评分策略、数据禁用项。
- [ ] 确认 `countsTowardQuota` 已从 false 变为 true（用一次提交后核对回执）。
- [ ] 记录每题公开榜单的量级（不记人名）：最高分、中位数、有效参与规模。
- [ ] 确认时区与截止时间（易错项）。

## B. 通道（0–10 分钟）

- [ ] CLI 可提交；回执字段可读（status/queue/额度）。
- [ ] trace validate 通过（真实原生会话）。
- [ ] dry-run 能出 bundle，体积在限内。
- [ ] 超时/重试/失败码处理已就绪。

## C. 首波提交（10–30 分钟）

- [ ] 每题至少 1 个已冻结的基线提交（或已排入提交队列）。
- [ ] 组合题入口按"最稳/最高价值子题在前"排列。
- [ ] 大包先瘦身再交。
- [ ] 提交后 60 秒内核对回执，异常按错误码处理。
- [ ] 台账记下每次提交的版本、时间、bundle 大小、额度余量。

## D. 监控（30 分钟后）

- [ ] 评分轮询已启动（10–15 分钟一次）。
- [ ] 记录每题 pending/scored/failed 数量。
- [ ] 对快速失败（2–9 分钟）与全 0 的 attempt 标记"疑似评测故障"，不要当质量分。
- [ ] 设定下一次复盘时间（2 小时后）。
