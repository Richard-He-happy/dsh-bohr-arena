# 单题循环与提分优先级

## 1. 单题 60–90 分钟循环

```text
轮询最新回执（5 分钟）
  → 对比"当前最好分 vs 期望上限"，定位差距来源
  → 选择动作：重交最优包 / 单变量改进 / 修 0 因 / 放弃
  → 本地官方 scorer 验证（≤30 分钟）
  → 真实 Agent 会话复跑关键步骤 + 采集 trace（≤10 分钟）
  → dry-run → 真投（1–2 发）
  → 记录台账，进入下一轮
```

## 2. 提分优先级（按 ROI）

| 优先级 | 动作 | 典型收益 | 判定 |
|---|---|---|---|
| P0 | 修 0 因：路径/格式/契约/trace/缺件 | 0 → 有分 | 回执错误码/字段缺失 |
| P0 | 口径修正：metric/匹配/单位/字段语义 | +10~+40 | 本地 scorer 对该口径敏感 |
| P1 | 主指标/高权重子题改进 | +5~+30 | 该子项权重 ≥0.3 |
| P2 | 单变量增强：TTA/后处理/校准/阈值 | +1~+10 | 本地与跨会话验证均为正 |
| P2 | 组合增强 | 叠加收益，风险更高 | 单变量已验证 |
| P3 | 文档/可复现证据 | 评审项，低成本 | 有时间再做 |

## 3. 决策规则

1. **一次只改一个因素**：多因素同时改动无法归因，容易在隐藏评测上翻车。
2. **同包重交**：平台取历史最高分时无下行；用于"内容已最优，只差评测条件"的情况。
3. **差距 >5 分且没有已验证方向**：不要靠重交赌，先找新设计或换题。
4. **单次低分不等于版本差**：先看评测耗时、子题分项、是否落在故障窗口。
5. **本地 val 高 ≠ 隐藏分高**：隐藏集若来自未见过的采集/分布，本地 val 可能完全失去排序能力；必须做跨会话/跨分布验证。
6. **拿满分的子题不要重复投入**：把额度留给有差距的子题。

## 5. 停止条件

- 多个独立方向都 <2σ（噪声级）改进，且各分项接近无真值上界 → 该题封顶，停止投入。
- 额度剩余不足以验证新方向 → 只保留最优包，不再实验。
- 平台故障持续且接近截止 → 按兜底策略提交最稳版本。
