# 多 Agent / 多人并行分工与提交纪律

## 1. 分工模型

| 角色 | 职责 | 产出 |
|---|---|---|
| 主线协调者 | 平台机制与提交、动态规划、额度台账、最终决策、对外汇报 | 提交记录、分数表、最终产物清单 |
| 构建者 | 按题构建产物：模型/解析器/管线/实验 | 可复现产物 + 说明 |
| 验证者 | 独立复算、契约审计、本地官方 scorer 判分、打包 QA | 验证报告、打包检查 |
| 调研者 | 题面/平台/公开方案/历史数据调研 | 机制表、参考基线、风险清单 |
| 监控者 | 评分轮询、故障识别、队列/额度状态 | 状态报告、告警 |

原则：**构建与验证分离**（自己验证自己容易漏），**提交单点**（避免并发冲突）。

## 2. 并行窗口

- 按题目拆并行窗口，每窗口一个构建者 + 明确产出目录；不要在同一个目录里并发写。
- 每个窗口有独立的任务说明与验收标准；产出物文件名、路径、schema 先约定。
- 合并在主线做：把多个窗口的产物合成一个包，合并脚本必须可重复执行、幂等。

## 3. 单点提交纪律

- 同一时间只允许一个提交执行器（由协调者或经其授权的脚本执行）；提交前检查锁/台账。
- 每次提交前：dry-run 通过 + 额度确认 + 产物已冻结（sha/字节数记录）。
- 提交后：把回执写入台账；分发给相关构建者。
- 禁止多人在不同窗口同时提交同一题（会触发冲突/重复计额度）。

## 4. 台账字段

| 字段 | 说明 |
|---|---|
| 时间 | 提交/出分时间 |
| 题 | 题目 key |
| 版本 | 内部版本号 + 一句话改动 |
| bundle 大小 / 摘要 | 用于对账与瘦身判断 |
| attempt 标识 | 唯一编号（内部台账用） |
| 状态 | queued/evaluating/scored/failed |
| 分数 / 分项 | 平台分与可读分项 |
| 额度余量 | 剩余提交次数 |
| 结论 | 保留/回滚/继续 |

## 5. 交接

- 冻结产物前写"交接说明"：目录、入口命令、依赖、已知限制、分数证据。
- 任何人接手前先读交接说明 + 跑一遍本地自检，不要直接改包。
- 比赛结束后把"最终产物 → 分数 → 证据"整理成一页盘点，便于下期复用。
