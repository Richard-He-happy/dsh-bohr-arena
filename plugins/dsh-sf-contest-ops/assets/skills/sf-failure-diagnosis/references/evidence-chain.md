# 证据链收集与故障报告结构

## 1. 证据清单

| 类别 | 具体材料 | 用途 |
|---|---|---|
| 时间线 | 故障起止、提交时间、恢复时间 | 证明故障窗口 |
| 同内容对照 | 两次提交的回执（分数/耗时/状态）+ 内容一致结论 | 证明不是答案差异 |
| 平台侧对照 | 同题公开 attempt 状态、同批其它题状态 | 区分单题/平台故障 |
| 本地复算 | 官方 scorer 分数、分项、契约检查结果 | 证明产物合规 |
| 产物材料 | 输出文件清单、行数、ID 唯一性、取值域检查 | 证明交付合规 |
| 复现材料 | 入口命令、依赖版本、运行日志摘要 | 便于对方复现 |

## 2. 报告结构（可直接改写使用）

```markdown
# 平台问题反馈（匿名）

## 摘要
一句话说明：哪题、什么现象、影响、当前状态（已恢复/未解决）。

## 问题 1：<现象>
- 故障窗口：<起止时间>
- 证据：
  1) 同一内容的两次提交：<时间/分数/评测耗时>，答题内容逐字节一致；
  2) 评测耗时 <异常短>，正常应为 <正常范围>；
  3) 同题/同批其它尝试是否正常：<结论>；
- 产物合规证据：<契约检查/本地复算/行数/唯一性>。
- 影响：<区间内的尝试未得到有效评测>。
- 诉求：<重评/补分/确认 grader 状态/说明配额>。

## 问题 2：<现象>
（同上结构）

## 附：最终成绩（供核对）
<题目、最高分、分项，不含个人信息与账号>
```

## 3. 写作要求

- 只写事实与证据，不写情绪化判断；推断要标"推断"。
- 不粘贴密钥、账号、本地绝对路径、平台内部 ID；用"同内容两次提交"代替具体编号。
- 长哈希只写"内容一致（本地校验通过）"，不贴完整值。
- 诉求要具体、可执行（重评/补分/修 grader/修配额说明）。
- 附上可复现的最小材料清单，便于对方核对。
