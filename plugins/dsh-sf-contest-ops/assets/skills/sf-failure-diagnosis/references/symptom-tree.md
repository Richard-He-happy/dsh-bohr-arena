# 故障症状决策树

```text
提交后没出分/出 0 分
├─ 提交本身失败（上传超时/网络错误）
│    → 上传通道故障 → 不消耗额度 → 恢复后重投同产物
├─ attempt 长期 queued（队列不动）
│    → 队列积压/worker 停摆 → 暂停提交，等队列推进 → 恢复后集中重提
├─ 评测很快结束且 0 分（2–9 分钟）
│    → 评测链路/租约故障 → 保留产物，等恢复；同内容重投可能更高分
├─ 同题全平台所有已评分 attempt 都是 0
│    → 该题评分器未生效 → 保留合规产物+证据 → 修复后立即重提
├─ 同包不同分（内容逐字节一致）
│    → 评测条件差异（租约容量/评分器状态）→ 取历史最高分，不改包
└─ 分数稳定偏低（分项与本地一致）
     → 真实分 → 从内容/口径/主指标改进入手
```

## 逐项检查清单

### A. 提交侧

- [ ] 回执是否有 attempt 标识与状态？
- [ ] 是否 429/409/422 等明确错误码？
- [ ] 上传耗时是否异常？bundle 大小是否超限？
- [ ] 同一产物重试是否成功？

### B. 评测侧

- [ ] 评测耗时是否显著短于正常值？
- [ ] 分项是全 0 还是有部分子项得分？
- [ ] 同题公开 attempt 是否正常出分？
- [ ] 同批其它题是否正常出分？

### C. 内容侧

- [ ] 本地官方 scorer 是否能正常判分？
- [ ] 契约字段/格式/入口是否齐全？
- [ ] 与上次正常出分的版本相比，改动是否单一、可解释？

### D. 证据侧

- [ ] 是否保存了故障前后的提交回执？
- [ ] 是否验证了两次提交内容一致？
- [ ] 是否记录了故障时间线？
