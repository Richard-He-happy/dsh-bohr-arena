# 第二期 10 题逐题打法（总览 + 阅读指引）

## 1. 怎么用

- 先在这里读"通用骨架"和"速查表"，再按题型进入参考文件：
  - 阅读类 5 题（文档解析 / 翻译 / 结构化笔记 / Nanopublication / 知识图谱）→ `references/tasks-r01-r15.md`
  - 写作类 5 题（润色 / 引用管理 / LaTeX / 引言 / 方法章节）→ `references/tasks-w02-w09.md`
- 每题一节固定四段：**目标与产物 → 评分点→实现映射 → 有效结构 → 失败模式**。
- 遇到同类新题面（换学科、换材料形态、换语言），用第 6 节"迁移法"套骨架，不要从零设计。

## 2. 两类题的通用骨架

### 2.1 阅读类（输入是材料，输出是结构）

```
盘点材料 → 抽取台账 → 结构化中间层 → 模型生成 → 确定性校验 → finalize
```

必备产物：可编辑主产物（md/jsonl/csv）+ `result.json`（16 字段）+ 证据矩阵。
共同高杠杆动作：

1. **证据矩阵**：每条结论/数字/断言/边 = claim + 逐字 quote + locator；匹配失败即不可核验。
2. **覆盖率有分母**：任务要求项数 / 已完成项数 / 缺失项列表，而不是只写百分比。
3. **`unknown` 三分类**：材料未报告 / 本次未覆盖 / 无法判断；三者处置不同，不能混写。
4. **页码不编造**：没有页映射就写章节+段落（`§Methods ¶3`），绝不写 `pN`。
5. **先落盘**：第一步写 partial `result.json`，之后每完成一块就覆盖一次。

### 2.2 写作类（输入是底稿与约束，输出是成稿）

```
读底稿/约束 → 计划（结构+来源） → 成稿 → 修改/来源映射 → 确定性校验 → finalize
```

必备产物：可编辑成稿（md/tex）+ 修改记录（`changes`）或论断-来源映射 + `result.json`。
共同高杠杆动作：

1. **只用素材**：不新增文献、作者、年份、期刊、DOI、数字；素材没有就不写。
2. **行内溯源**：每个数字/引用同行带 `[S#]`（或等价标记），否则视为不可核验。
3. **保护性 spans**：数字、单位、引用编号、公式、图表指向、专名在改写/整理中逐字保持。
4. **最小编辑 + 逐处记录理由**：before / after / type / reason / 位置 五要素齐全。
5. **状态诚实**：有占位符（`〔待补:…〕`）就 `partial`，不为了好看写 `ok`。

## 3. 10 题速查表

| # | 题 | 类 | 核心产物 | 最关键评分点 | 最大风险 |
|---|---|---|---|---|---|
| 1 | 文献文档解析 | 读 | 正文/章节/表格/公式/图表位置的结构化解析 + 证据 | 提取完整且不串栏、页码可回查 | 把全文当结果、双栏错序、页眉页脚混入 |
| 2 | 文献翻译 | 读 | 段落级双语对照 + 术语表 + 依据 | 术语全篇一致、数字引用不变、段号对齐 | 只给大意、术语漂移、漏段 |
| 3 | 文献总结与结构化笔记 | 读 | 章节对齐笔记 + 知识点清单 + 锚点 | 笔记骨架=论文自身章节、每条可回原文 | 通读摘要、编页码、quote 改写 |
| 4 | Nanopublication | 读 | 断言-证据-来源三段式结构 | 断言单一可判真假、证据最小充分、可机器解析 | 整段当一个断言、证据错位、无受控词表 |
| 5 | 文献知识图谱构建 | 读 | 节点-边图谱 + 证据 + 可执行查询 | 实体真实出现在原文、关系有证据、别名归一 | 常识补全、共现当关系、同名误合并 |
| 6 | 学术语言润色 | 写 | 改后全文 + 逐处修改记录 | 最小编辑、限定强度守恒、术语统一 | 整段重写、数据被顺手改、无记录 |
| 7 | 参考文献与引用管理 | 写 | 可编辑稿件 + 同步文献表 + 合并/编号记录 | 引用挂到论断、编号双向同步、去重可解释 | 引用挂段末、只改正文、误合并 |
| 8 | LaTeX 写作与编译 | 写 | 可编译 .tex + 构建说明 + 修复记录 | 编译通过、错误归因到行、模板必填齐 | 只交 PDF、停在第一条错误、乱加宏包 |
| 9 | 引言与相关工作写作 | 写 | 四段式引言 + 来源清单 + 论断映射 | 无引用不断言、空白有出处、贡献可锚定 | 编造文献、逐篇摘要拼接、空话开场 |
| 10 | 方法与实验章节写作 | 写 | 章节成稿 + 参数/事实台账 + 缺口清单 | 参数与日志/配置一致、可复现、缺口显式 | 为通顺补数值、基线不可比、示例依赖第三方 |

## 4. 跨题通用的 6 个提分杠杆

1. **证据矩阵**：把"结论"与"原文逐字片段+位置"绑定；这是"可核验性"与"使用增益-可验证"两项的唯一硬通货。
2. **覆盖率计数**：`required / done / rate / missing` 四件套；judge 能一眼看出完整度，也逼自己不漏项。
3. **受控词表**：关系类型、编辑类型、实体类型、缺口级别都用固定枚举；比自由文本更可复核、更可被下游解析。
4. **双向同步**：编号↔列表、术语↔全篇、贡献↔正文、节点↔边，凡是"两处必须一致"的都要有机检。
5. **负例与降级**：空输入、坏 JSON、无文本层、材料冲突各准备一条分支；能降级交付的题，稳定性分会明显更稳。
6. **契约透传与状态诚实**：`output_contract` 原样回填、`status` 由计数决定；这两点是"零成本但高权重"的评分点。

## 5. 失败模式总表（跨题共性）

| 模式 | 症状 | 根因 | 对策 |
|---|---|---|---|
| 内容空转 | 产物"看起来像"，但没有结构、没有定位 | 把"写一段好文字"当交付 | 先定字段与证据，再生成文本 |
| 结构膨胀 | 文件 27–28、240–300KB、脚本 6 个 | 以为功能越多分越高 | 回到精简骨架；新增结构必须直接对应评分点 |
| 路径/入口错 | 只有 scripts、SKILL.md 不在根、引用文件缺失 | 打包与布局没校验 | 提交前脚本化检查路径与入口 |
| 运行期崩溃 | 0 分 / `evaluation_error` | 第三方依赖、CWD 依赖、大脚本超时、示例脚本副作用 | 纯标准库、`__file__` 自算、退出码 0、示例不 import 重依赖 |
| 证据造假 | 页码/quote 拼凑 | 没有抽取台账就写结论 | 先抽台账再生成；找不到就 `unknown` |
| 状态虚高 | `ok` 但覆盖率一半 | 自评代替规则 | status 由覆盖率与校验计数决定 |
| 方差误判 | 一次低分就改方向 | 把评测波动当版本问题 | 同包重投 3 次再判断 |

## 6. 迁移法：拿到同类新题怎么套（4 步）

1. **判类型**：产物是"结构/证据"（阅读类）还是"成稿/映射"（写作类）？先抄对应通用骨架。
2. **抄最近的题**：找评分点最接近的一题做基线，只改两处——① 任务专属质量规则（第 7 节那种映射表）② 主产物文件名与字段。
3. **rubric 落表**：把题面五维拆成 12–20 条检查项，逐条写"要素 → 字段 → 机检项 → 产物位置"；落不进表的评分点，就是还没设计好的部分。
4. **对照历史分数定预期**：结构化强、可机械核验的题（解析、翻译、笔记、方法章节）用"精简 + 证据"能到中高分；依赖真实文献元数据或领域知识深度的题（引用核验、知识图谱）不要承诺做不到的能力，先把"可核验部分"做满。
