# 写作类 5 题逐题打法（tasks-w02-w09）

> 通用骨架见 `SKILL.md` 第 2.2 节。每题给出：目标与产物、评分点→实现映射、有效结构、失败模式、二期实测。
> 分数只保留相对变化；结构数据来自二期最好版本的包体观察。

## 6. 学术语言润色

**目标**：在保持原意、限定强度、数据、单位、引用编号与图表指向不变的前提下，逐句做最小编辑润色，并交付改稿与逐处修改记录。
**四个关注**：改得对（语法/搭配/标点真的改掉，不是换说法掩盖）、说得像（目标文体与语域、术语全篇统一）、没改坏（原意/限定/数据/引用/图表指向不变）、讲得清（每处修改有原文、改文、类型、理由）。

**输入 / 产物**：原稿（纯文本/Markdown/LaTeX 片段/章节稿）+ 术语表与风格约束 + `output_contract`；产物 `polished.md`（改后全文）、`changes.csv`（位置/原文/改文/类型/理由）、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 指定章节逐段处理；术语表建全；缩写/符号首次出现统一 | `coverage` + `changes[]` |
| 正确性 15 | 不可编辑区保护：数字/单位/引用编号/公式/图表指向/专名逐字不变 | 保护性 spans 检查 |
| 完整性 5 | 中英双语对照（如要求）+ 修改清单 + 术语表齐全 | 主产物清单 |
| 可核验 5 | 每处修改 before/after 可对照，理由可判断"该不该改" | `changes[]` 五要素 |
| 使用增益 25 | 限定强度守恒、术语一致率可计数 | `verification.checks` |
| 可靠 10 | 超长输入、编码混乱、公式引用混杂的处置 | 分支表 + `degradations` |

**有效结构**：SKILL.md 执行协议 + 1–2 个纯标准库脚本（prepare/verify/finalize 或等价）+ 4 类资源（编辑类型词表、限定词分级词表中英、文体/风格指南、术语表格式）+ `before_after_digest`（输入/契约/输出一致性比对，发现漂移回退原文）+ 回读通道（改后回读校验）+ **负路径测试**（数字篡改、限定词加强、引用删除、数学改动、否定移除都必须被拒并回退）。
**二期实测**：首版 75（14 文件 / 128KB / 1 脚本）→ 最好 77.33；v2 加功能到 27 文件掉到 67.67；最好分仍来自"早期精简版 + 重 roll"。

**失败模式（3–6 条）**：
1. 整段重写导致限定词消失或被加强（把"可能"改成"会"）。
2. 顺手改了数字、单位、引用编号或图表指向。
3. 术语在标题/摘要/正文/图注间漂移，术语表没有回扫。
4. 没有修改记录或记录缺"理由"，无法判断该不该改。
5. 纯内容问答时误触发改写（触发条件写得过宽）。
6. 过度同义替换造成专业含义偏移。

## 7. 参考文献与引用管理

**目标**：从真实稿件与文献库出发，完成引用插入、编号更新、去重、格式转换与来源核验，交付可继续编辑的稿件与同步文献表。
**四个关注**：挂得对（引用落在真正需要来源支撑的论断句）、编得顺（增删调序后正文编号与文末列表同步、连续、样式一致）、收得净（同一文献的中英文题名/预印本/不同数据库导出能合并并给出依据）、对得上（每条引用真实存在、元数据准确、论断与所引文献匹配）。

**输入 / 产物**：稿件 + 文献库导出（BibTeX/RIS/EndNote/CNKI）+ 目标规范（如 GB/T 7714、指定 APA 版本）；产物 `manuscript.md`（或覆盖稿）、`bibliography.csv`（条目+来源+状态）、`ledger.csv`（原编号→新编号→改动）、`dedup_report.md`、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 六类动作（插入/编号/去重/转换/核验/一致性）+ 全章节覆盖 | 动作清单 + `coverage` |
| 正确性 15 | 每条引用落到可定位记录；论断与文献主题匹配 | `citations[]` + 匹配依据 |
| 完整性 5 | 全部引用点与全部条目；字段补齐（DOI/卷期页/类型标识） | 计数 + `bib` 字段检查 |
| 可核验 5 | 原稿→成品→原编号映射→匹配依据全链路 | `ledger.csv` |
| 创新 15 | 编号连锁更新、正文↔列表双向同步、去重决策可解释 | 算法 + 报告 |
| 可靠 10 | 字段缺失、DOI 失败、条目歧义、编号冲突的处置 | 分支表 |

**有效结构**：9 文件 / 137KB / 1 脚本；`styles/*.json`（目标规范）+ `dedup_rules`（DOI/题名/预印本判据与阈值）+ `citation_placement`（论断级插入）+ `ledger.schema.json` + 负例（同名作者不同文献、中英文题名重复、预印本与正式版）。
**二期实测**：首版 66 → 最好 66（零提升）；v2（28 文件）56、v3 52。核心教训：把"真实检索与原文核验"当成可离线完成的事，承诺了做不到的能力。

**失败模式（3–6 条）**：
1. 引用统一插到整段末尾，不落到论断句 → "挂得对"不达标。
2. 只改正文编号，文末列表/图表注/附录不同步。
3. 去重误合并（同名作者的不同文献）或该合的不合。
4. 字段缺失不标 `unknown`，靠"常见值"补齐或编造 DOI。
5. 只做格式转换，没有来源核验与"论断-文献"匹配。
6. 6 个脚本串行链路过长，隐藏案例形态一变就失败。

## 8. LaTeX 写作与编译

**目标**：交付能在指定模板与 TeX 发行版下编译通过、可并入稿件的 `.tex` 成果，并给出可复现的构建记录。
**四个关注**：编译得通（按预期轮次通过，报错能定位到文件/行号/根因）、改得对（公式符号编号、表格数值列宽、交叉引用与文献、模板必填项都符合意图与模板）、交得可用（结构清楚、可继续编辑维护的源码，不是 PDF/截图/片段）、复现得了（模板版本、宏包、字体、编译命令与轮次可重复）。

**输入 / 产物**：已有稿件/工程 + 模板约束 + 参考文献 bib；产物 `main.tex`（+ 子文件）、`BUILD.md`（引擎、轮次、宏包、字体、命令）、`result.json`（含编译状态、修复清单、日志路径）；有编译能力时附真实 PDF 预览。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 任务要求的改动点、模板必填项、配套文件逐项覆盖 | 清单 + `fixes[]` |
| 正确性 15 | 公式符号/编号、表格数值/列宽、交叉引用与文献一致 | lint 检查项 |
| 完整性 5 | 源码 + bib + 构建说明 + 必要资源齐备 | 包清单 |
| 可核验 5 | 改动可定位到文件行；编译日志可回看 | `fixes[]` + `build.log` |
| 创新 15 | 错误分类、修复策略、编译验证闭环 | 规则文件 + 报告 |
| 可靠 10 | 缺宏包/缺字体/级联报错/模板类缺失的处置 | 分支表 |

**有效结构**：可稳定运行的形态是 11 文件 / 115KB / 1 脚本（首版 62 分）；71 分由同包重 roll 得到。`lint_rules.json`（未定义引用、重复 label、宏包冲突、数学符号）+ `log_rules.json`（错误分类与归因）+ `skeleton_main.tex` + `result_schema` + 示例工程；只用标准库解析日志，不依赖在线编译。
**二期实测**：首版 62 → 最好 71（重 roll）；v2 加功能到 27 文件直接 0 分。风险极高、收益中等。

**失败模式（3–6 条）**：
1. 只交 PDF/截图/片段，不交可编译源码。
2. 没有编译环境也不声明，直接把未验证源码当成品。
3. 报错只处理第一条，级联错误未清。
4. 反复加宏包导致"修一处坏一处"。
5. 模板必填项（作者/单位/摘要/关键词/参考文献格式）缺失。
6. 大改版导致 evaluation_error / 0 分。

## 9. 引言与相关工作写作

**目标**：基于给定素材写出可直接进论文的引言与相关工作（研究背景、相关工作、研究空白、贡献），引用落在具体论断上。
**四个关注**：立得住（背景指向真实脉络与具体未解决问题）、分得清（相关工作按问题/方法/路线分组比较，不是逐篇摘要）、说得实（空白由已引文献缺口推出，断言有证据或标为作者判断）、对得上（贡献与实际方法/图表/结果一一对应，引用元数据可核对）。

**输入 / 产物**：`case.json` + task.md + 素材（论文/摘要/参考文献库）；产物 `manuscript.md`（四段式）、`sources_used.md`（仅素材来源的编号清单）、`claim_source_map.md`（论断→来源）、`change_log.md`、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 四部分齐全且承接；引用落在具体论断 | 四节结构 + 引用检查 |
| 正确性 15 | 只转述素材写明的结论；元数据真实；空白有出处 | `claim_source_map` |
| 完整性 5 | 主要方法路线、关键工作、必要字段（作者/年份/来源）覆盖 | `sources_used` + 覆盖计数 |
| 可核验 5 | 每条引用可回来源；分组依据/空白推导/贡献对照可复核 | 映射文件 |
| 创新 15 | 引用与论断绑定、按路线分组比较、空白推导、贡献对齐 | 配方 + 校验 |
| 可靠 10 | 素材不足/文献库空/格式未知时的诚实降级 | `pending_human` |

**有效结构**：7 文件 / 95.7KB / 1 脚本；`resources/prompts.md`（四段写作模板、分组矩阵、转述与空白推导句式、禁用词表）+ `checklist.md` + `result_template.json`；脚本子命令 `prep / sources / check / map / finalize`，一步一响应；六条铁律（只用素材、编号一致、无引用不断言、空白要推出、贡献可对照、不确定就标注）。
**二期实测**：首版 68 → 最好 73（重 roll）；引用覆盖率与"无引用断言"是主要扣分点。

**失败模式（3–6 条）**：
1. 编造文献、作者、年份、期刊、DOI 或数字。
2. 相关工作按年份逐篇罗列，没有分组与比较维度。
3. 研究空白没有出处（凭空说"尚未研究"）。
4. 贡献条目没有锚点（章节/图/表/数字）。
5. 以"近年来受到广泛关注"开头，空转铺垫。
6. 引用编号与来源台账不一致、引用挂空。

## 10. 方法与实验章节写作

**目标**：把散落的实验材料（配置、日志、代码、数据说明）整理成可复现的方法与实验章节，并交付台账、缺口与冲突清单。
**四个关注**：写得全（步骤/设置/参数/数据集与划分/对照/重复次数）、写得准（参数、版本、条件与配置和日志一致，不为顺畅补数值）、做得着（按章节能复做：版本、环境、种子、命令齐全）、说得住（缺口与不确定显式标出，限制条件指向具体失效场景）。

**输入 / 产物**：`case.json` + 配置/日志/代码/数据说明；产物 `manuscript.md`（十节：数据、步骤、设置、参数、基线、复现清单、限制…）、`fact_ledger.csv`、`parameter_ledger.csv`（名称/取值/单位/作用对象/来源）、`evidence_matrix.csv`、`gaps.md`、`conflicts.md`、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 六类要素（步骤/设置/参数/数据集/基线/复现限制）逐项覆盖 | `coverage` 六键 |
| 正确性 15 | 每个数字同行有 `[S#]` 溯源；冲突三源保留 | 检查 C6/C9 + `conflicts` |
| 完整性 5 | 台账表头齐全、证据矩阵六行齐备 | 台账 schema |
| 可核验 5 | 每条参数/步骤可追到具体材料（文件+locator+quote） | `sources[]` |
| 创新 15 | 从代码/配置/日志抽要素 → 对齐正文 → 发现缺口并追问 | 抽取清单 + 缺口模板 |
| 可靠 10 | 材料缺失/配置冲突/参数无源的降级 | 12 条分支表 |

**有效结构**：14 文件 / 91.6KB / 2 脚本（最大 27.8KB）→ 首版 61、v2 加功能 0 分、v3 精简 72.67、重 roll 到 76.67。核心是：六类要素清单 + 十节 blueprint + 三张台账 schema + `[S#]` 行内溯源 + 冲突保留策略 + 缺口占位（`〔待补:Gxx〕` 联动 `gaps.md`）。
**二期实测**：61→76.67，是该期提升最大的一题；提升全部来自"精简 + 台账 + 校验"，不是加功能。

**失败模式（3–6 条）**：
1. 为了让段落顺畅补出配置里没有的数值或"默认值"。
2. 参数无来源、数据集版本/划分含混 → 可复现性差。
3. 基线不可比（不同预算、不同指标口径）却写成"优于基线"。
4. 只写主干步骤，缺少设置/种子/重复次数。
5. 冲突信息被悄悄统一成一个值。
6. 示例或夹具 import 第三方库，导致示例扫描阶段直接崩溃 → 0 分（二期最昂贵的教训之一）。
