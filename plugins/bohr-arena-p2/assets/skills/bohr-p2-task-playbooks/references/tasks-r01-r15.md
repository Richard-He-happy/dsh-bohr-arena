# 阅读类 5 题逐题打法（tasks-r01-r15）

> 通用骨架见 `SKILL.md` 第 2.1 节。每题给出：目标与产物、评分点→实现映射、有效结构、失败模式、二期实测。
> 分数只保留相对变化；结构数据来自二期最好版本的包体观察。

## 1. 文献文档解析

**目标**：把真实 PDF 解析成"可继续处理"的结构化结果（正文、章节、表格、公式、图表位置），而不是一段"看起来像全文"的文本。
**四个关注**：提得全（正文/题注/脚注/参考文献逐字、不漏行、页眉页脚不入正文）、排得对（双栏/多栏/跨页按原版面顺序）、拆得清（章节层级、表格行列、公式上下标）、核得回（每段每表可指回页码与区块）。

**输入 / 产物**：输入 `/input/case.json` + task.md + 实际 PDF（无预抽取答案层）；产物建议 `parsed.md`（分节正文）+ `structure.json`（sections/tables/figures/formulas）+ `result.json` + 证据矩阵。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 正文/题注/脚注/参考文献逐字提取；每个结构元素进数组 | `structure.json` 计数 + `parsed.md` |
| 正确性 15 | 阅读序规则（栏检测→行聚类→跨栏接续）；页眉页脚黑名单与重复行剔除；相邻段不拼接 | 抽取脚本的 S1/S2 检查 |
| 完整性 5 | 标题/作者/单位/摘要/章节/图表题注/公式编号/参考文献逐项打勾 | 结构清单 + 覆盖率 |
| 可核验 5 | 每段带页码与区块；表格带页码+表号 | `evidence[].locator` |
| 可靠 10 | 无文本层/加密/乱码 → 降级阶梯 + `pending_human` | 分支表 + `degradations` |
| 生态 10 | 结构 schema、版本/版式样本、限制说明 | `resources/` |

**有效结构**：SKILL.md（流程+阅读序规则+结构定义）+ 1–2 个纯标准库脚本（盘点/抽取、结构校验）+ 结构 schema + 覆盖率清单；若平台案例自带 PDF 文本抽取或 OCR 工具，写"检测 → 调用 → 失败降级"分支，比自写解析更稳。
**二期实测**：首版 58 → 最好 66.33；最好分来自**砍功能后的极简版**，而大而全版本分数更低；该题长期未进入高分区间，主要瓶颈是自写解析的版式识别上限。

**失败模式（3–6 条）**：
1. 只输出整篇文本、没有 sections/tables/figures 结构 → 完成度与完整性双低。
2. 双栏按"先左后右、逐行拉平"处理 → 串栏、断句拼接。
3. 页眉页脚、页码、水印混进正文首尾行。
4. 扫描件/无文本层不标 `unknown`，用猜测文字补齐。
5. 表格行列拍平成一个字符串，行列归属丢失。
6. 页码编造或全部写 `p1` → 可核验性 0。

## 2. 文献翻译

**目标**：把文献译成可复核的双语对照，术语、指代、否定与限定、数字单位、公式与文献编号都要与原文一致。
**四个关注**：术语稳（标题/摘要/正文/图注/结论同一译名）、段落全（跨页跨栏不漏不重、段号对应）、关系准（指代/否定/限定/因果让步/数字单位/公式引用）、可核验（每段能指回原文并说明译法依据）。

**输入 / 产物**：输入论文 PDF/TXT/DOCX/HTML 或 `case.json` 内嵌正文；产物 `translation.md`（段号+原文+译文+依据）、`glossary.csv`（源词/锁定译名/状态/证据段号+quote）、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 段落级双语对照，而非大意；段号与原文一一对应 | `translation.md` + `coverage` |
| 正确性 15 | 术语表锁定（10–40 条）+ 全篇回扫；数字/单位/公式编号/引用标记保护检查 | 检查项 S4–S7 |
| 完整性 5 | 图表题注、表头、公式、引用标记、术语表条目是否覆盖 | 计数 + `coverage` |
| 可核验 5 | 每条关键结论/数字/术语带逐字 quote | `evidence[]`（S8 校验） |
| 可靠 10 | 无文本层/双栏错乱/术语冲突的处置 | 分支表 |

**有效结构**：7 步流程（盘点→切段→建术语表→逐段翻译→机械核验→只改 fail 的段→无条件 finalize）；术语"没有 quote 不锁定"；三种占位符语义分开（`〔待补:…〕`未做 / `〔未译:…〕`脚本占位 / `〔存疑:…〕`已译不确信）；`coverage_rate=1.0` 且 `fail_count=0` 才允许 `ok`。
**二期实测**：首版 72 → 最好 76（重 roll）；最好版本 23 文件 / 189KB / 6 脚本，核心是"术语表 + 机械核验"而不是更花哨的翻译提示。

**失败模式（3–6 条）**：
1. 只给摘要或改写，没有段落级对照 → 完成度低。
2. 术语表只写在 SKILL.md 提示里，没有脚本回扫 → 全篇漂移。
3. 跨页/跨栏漏段或重复翻译；段号自造导致无法对齐。
4. 润色式翻译改动了数字、单位、否定范围。
5. quote 不在原文（回译、补省略、改标点）→ 证据不可核验。
6. finalize 依赖前序成功，异常时 0 产出（必须无条件导出）。

## 3. 文献总结与结构化笔记

**目标**：把论文变成"与论文自身章节对齐、字段齐备、可回链复核、可继续复用"的笔记。
**四个关注**：对得上（骨架=论文自身章节，不是通用摘要模板）、留得住（研究问题/数据/方法条件/主要发现/局限）、找得回（章节/段落/页码/图表锚点）、用得上（可检索、可比较、可继续加工）。

**输入 / 产物**：论文 PDF/TXT/DOCX 或 `case.json` 内嵌正文；产物 `notes.md`（章节对齐表+分节笔记+证据表）、`knowledge.jsonl`（一行一条知识点）、`extraction_index.json`（切分与页映射）、`run_log.md`、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 按原文标题切章节，逐节写目的/方法/结果/结论 | `sections[]` |
| 正确性 15 | 论断数值/条件与原文一致；quote 逐字 | `evidence[]` + `verified_*` |
| 完整性 5 | 论文卡片六字段（问题/数据/方法条件/发现/局限/结论）齐全 | `paper_card` |
| 可核验 5 | 锚点优先级：`p12` → `§Methods ¶3` → `L120-134` → 无页不写页码 | `anchor` 字段 |
| 可靠 10 | 扫描件/图表缺失/超长文的降级 | L0–L4 降级阶梯 |

**有效结构**：单脚本多子命令（`extract / show / check / finalize / selftest`）+ 分批写 JSON 草稿（`part_1/2/3.json`）+ **先 finalize 再补**；`status` 由覆盖率规则决定（核心章节覆盖≥75%、已笔记章节≥3、通过校验引文≥2）；锚点状态分 `verified_page / verified_loose / verified_inline / not_found`。
**二期实测**：首版 73.67 → 最好 79.33；最好版本 5–6 文件 / 116–168KB / 1–2 脚本；后续"改进版"全部更低（文件越多、脚本越多越低）。

**失败模式（3–6 条）**：
1. 通读式摘要代替分节笔记 → 骨架与论文不对齐。
2. 无页映射却写页码；或把估算页码写成事实。
3. quote 被改写、翻译或拼接 → 逐字校验失败。
4. `unknown` 三分类混用（未报告/未覆盖/无法判断写成一类）。
5. 一次读整篇导致预算耗尽、后续章节缺失。
6. `status` 自评成 success 但覆盖率不达标。

## 4. Nanopublication

**目标**：把论文关键结论拆成可独立判断真假的断言，绑定最小证据片段与来源元数据，输出可机器读取的结构。
**四个关注**：拆得细（一段结论拆成多条单一断言，保留条件与限定）、对得上（最小充分证据片段 + 原文位置）、追得回（断言-证据-论文-作者-年份-版本链路）、读得懂（字段与序列化形态可被下游直接解析）。

**输入 / 产物**：论文材料（文本/PDF）；产物 `assertions.json`（断言：subject/predicate/object/conditions/evidence_ids）、`provenance`（来源元数据）、`publication`（标识符/版本），合起来是三段式结构；另有 `result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 每条断言单一、可判真假，复合句拆开 | `assertions[]` |
| 正确性 15 | 主体与关系方向准确；证据片段真的支持该断言 | `evidence_ids` + 校验 |
| 完整性 5 | 断言/主体关系/证据片段/证据位置/来源元数据/置信度依据/标识符齐全 | 字段清单 |
| 可核验 5 | 每条断言可回到原文逐条确认 | locator + quote |
| 创新 15 | 断言粒度判据、证据最小充分性判据、关系受控词表、去重合并规则 | `resources/` 规则文件 |

**有效结构**：三段式 schema + 受控关系词表 + 断言规则 + 置信度 rubric + 去重/合并规则 + **负例夹具**（重复 id、错页、坏 quote、缺 locator、未映射 predicate）+ 逐段验收脚本。
**二期实测**：首版 59 → 最好 73（多轮小步：59→66.67→70.33→73）。该题是"加结构反而有效"的例外：73 分版本是 28 文件 / 291KB 的完整结构——因为断言/证据/来源的**结构本身就是评分对象**。

**失败模式（3–6 条）**：
1. 整段话塞进一个"断言"字段 → 拆解粒度不达标。
2. 证据片段跨段/错位，或只给段落号不给片段。
3. 关系类型自由填写、无受控词表 → 关系判定不可复核。
4. 主体混淆（作者自述被他人的结论当成本文结论）。
5. 来源元数据缺失或编造年份/版本。
6. 结构文件不合法（JSON 带注释、重复 id、缺必填）→ 下游不可解析。

## 5. 文献知识图谱构建

**目标**：从一批论文抽取实体与关系，绑定证据，输出可查询的图谱。
**四个关注**：抽得准（实体真实出现在论文中）、连得对（关系类型/方向/适用条件与原文一致，不把共现当证据）、对得齐（别名/缩写/大小写/同名冲突处理，既不重复也不误合并）、查得到回得去（能答真实查询，节点与边能回原文）。

**输入 / 产物**：论文集合 + 任务书；产物 `graph.json`（nodes/edges，带 evidence）、`annotations.md/jsonl`、至少 3 个真实查询及结果、`result.json`。

| 评分点 | 实现动作 | 落点 |
|---|---|---|
| 完成度 15 | 实体类型（研究者/材料/方法/任务/指标/结论）+ 关系类型齐备 | 词表 + schema |
| 正确性 15 | 每条边有原文证据；关系方向与适用条件准确 | `edge.evidence` |
| 完整性 5 | 节点/边/证据字段/查询问题都覆盖 | `coverage` |
| 可核验 5 | 节点与边可回查论文位置与原文片段 | locator + quote |
| 创新 15 | 跨篇对齐、证据绑定、增量更新（保留既有 id） | 规则文件 + 查询 |

**有效结构**：实体类型与关系类型词表 + 规范化规则（别名/缩写/同名）+ 冲突策略 + 证据规则 + 查询 playbook + 图谱 schema；8–10 文件 / 125–192KB / 1–2 脚本是二期较好形态。
**二期实测**：首版 59.33 → 最好 61（仅 +1.67），是该期最难突破的题。短板明确：依赖自写解析与常识式抽取，实体与边的质量上限被压低，且未利用平台自带工具。

**失败模式（3–6 条）**：
1. 实体是模型常识补全的，不是原文出现的表述。
2. 把共现、综述转述、推测当成直接证据建边。
3. 关系方向反了，或忽略"在条件下成立"。
4. 不区分作者自述与他人转述；同名实体误合并或同实体重复建点。
5. 没有真实查询，只交"一堆节点和边"。
6. 脚本多（6 个）、包大（285KB+）导致运行稳定性差，反而掉分。
