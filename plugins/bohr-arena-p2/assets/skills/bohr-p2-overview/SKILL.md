# 玻尔产品赛第二期（学术写作全流程）全景

## 1. 用途与边界

- **用**：复盘第二期 10 题怎么打；判断某类题是否值得继续投入、该用什么手段提分；给同类「隐藏案例运行 + rubric 打分」的学术写作 Skill 竞赛排计划。
- **不用**：查具体提交命令与排障（→ `bohr-p2-submission-ops`）；写 Skill 包的规范细节（→ `bohr-p2-skill-blueprint`）；某道题的结构配方（→ `bohr-p2-task-playbooks`）。
- 本文件只保留相对经验：分数、区间、变化幅度；不含身份信息、个人名次与提交级标识。

## 2. 赛事结构：10 题 = 2 类

二期共 10 道 `product-arena` 题，只提交 Skill 本体（SKILL.md + scripts + resources）。平台把 Skill 装进官方 Harness，在 3 个固定隐藏案例上各真实运行一遍，再由 judge 按题面 rubric 打分。

| 类 | 题 | 核心产物 | 共同难点 |
|---|---|---|---|
| 阅读类 r | 文献文档解析、文献翻译、文献总结与结构化笔记、Nanopublication、文献知识图谱构建 | 解析结果 / 双语对照 / 结构化笔记 / 断言-证据结构 / 节点-边图谱 + `result.json` | 抽取准确、定位可回查、结构可机器读 |
| 写作类 w | 学术语言润色、参考文献与引用管理、LaTeX 写作与编译、引言与相关工作写作、方法与实验章节写作 | 可编辑成稿（md/tex/csv）+ 修改或来源映射 + `result.json` | 事实不漂移、每个数字/引用有来源、能编译或能继续编辑 |

两类共同契约：`result.json` 保留 `case_id`、主结果、证据/来源定位、运行状态、不确定性与人工接管项；输入含 `output_contract` 时原样回填。三案例、每条件三次重复；参赛者不自带测试案例，也不能交预制答案。

## 3. 评测模型：harbor replay + 3 隐藏案例 + rubric 五维

评分公式（题面公开）：**实际效果 40 + 使用增益 25 + 创新增益 15 + 可靠体验 10 + 生态贡献 10 = 100**。

| 维度 | 子项 | 判分实际看什么 | 对 Skill 的硬要求 |
|---|---|---|---|
| 实际效果 40 | 完成度 15 / 正确性 15 / 完整性 5 / 可核验性 5 | 是否真的跑完并交付可继续使用的产物，而不是"像结果的一段话" | 主产物可编辑；关键结论逐字 quote + locator |
| 使用增益 25 | 质量 15 / 效率 5 / 可验证 5 | 相对"不加载 Skill 的基础 Agent"的净提升；文字自述不算证据 | 契约字段齐全；覆盖率与通过计数可复核 |
| 创新增益 15 | 新增能力 5 / 方法 5 / 证据 5 | 基础 Agent 难稳定做到的能力（跨页接续、字段化回链、双向同步…） | 把能力落成可执行的检查与产物位置 |
| 可靠体验 10 | 调用 3 / 稳定 4 / 异常 3 | 能否触发、重复运行是否一致、坏输入是否降级 | 退出码恒 0、先写 partial、异常分支表 |
| 生态贡献 10 | 文档 3 / 复用 4 / 推广 3 | 换学科/换样本能否直接复用 | 字段字典、规则文件、最小示例齐备 |

**核心事实**：分数来自「在隐藏案例上真的跑完并产出可复核结果」，不是 SKILL.md 写得多。文件数、脚本数与功能量都不直接进分；只有"跑通 + 输出质量"进分。

## 4. 成绩演进与提分/掉分规律

**演进**（首版 → 该题最好分）：解析 58→66.33；翻译 72→76；笔记 73.67→79.33；Nanopublication 59→73；图谱 59.33→61；润色 75→77.33；引用管理 66→66；LaTeX 62→71；引言 68→73；方法章节 61→76.67。10 题最好分分布在 61–79.33。逐题明细见 `references/score-log.md`。

规律（二期实测）：

1. **重 roll 是唯一被反复验证的提分手段**。同包重复提交的分数波动常见 **8–15 分**；最好分几乎都是多次提交的上尾，不是稳定能力。
2. **"加功能"几乎必然掉分**：润色 75→67.67、笔记 73.67→69.67、引用管理 66→56、LaTeX 62→0、方法章节 61→0。这些"完整版"的共同点是文件 27–28 个、总大小 240–300KB、脚本变多。
3. **"小而稳"能一次提 5–12 分**：方法章节 61→72.67（14 文件 / 2 脚本 / 93KB）；解析题极简版 58→66.33。
   - 例外：Nanopublication 的 73 分版本是 28 文件 / 291KB 的完整三段式结构——当"结构本身"就是评分对象（断言 / 证据 / 来源）时，适度复杂不吃亏；判断标准是"新增结构是否直接对应评分点"。
4. **评测方差与平台漂移叠加**：同一时期平台整体校准下移约 5 分，新旧版本同时下降；因此单次低分不能否定版本，单次高分也不能证明方向对。
5. **结构性重写无增益**：用强模型改写既有 SKILL.md、或从零重写整题，结果都落在原版本分布内；瓶颈是隐藏案例上的实际输出质量。
6. **0 分与低分是两件事**：0 分/`evaluation_error` 是运行或判分失败（脚本脆弱、依赖、包不完整、trace 不可读），低分是质量不足。前者先修通道，后者才谈内容。

## 5. 可行 / 不可行清单

| 判定 | 做法 | 依据 |
|---|---|---|
| ✅ 可行 | 早期精简版打底（≤10 文件、≤120KB、1–2 个纯标准库脚本），先保证跑通与落盘 | 多题最好分都来自精简版 |
| ✅ 可行 | 对差距小的题用历史最好版本重 roll 3–5 次取最高 | 翻译、引言、LaTeX、方法、笔记、Nanopublication 均如此提分 |
| ✅ 可行 | 小补丁：相对最好版本 +≤3 文件 / +35KB / +1 脚本，一次只改一类问题 | 大改多掉分 |
| ✅ 可行 | 提交前红队自检：按 rubric 六项逐条找 blocker（包不完整、引用缺失、frontmatter 不合法） | 提前挡住失败 |
| ❌ 不可行 | 堆功能/堆脚本/堆资源的"完整版" | 上节第 2 条的五个实测掉分 |
| ❌ 不可行 | 强模型改写既有多文件 Skill 求增益 | 三次改写/重写全部落在原分布 |
| ❌ 不可行 | 对差距 >5 分的题做重 roll | 纯方差，期望收益趋零 |
| ❌ 不可行 | 用"prompt + answer"两条消息合成 trace | 一批 11 条提交中 7 条 failed；换原生会话 trace 后 15+ 条 0 failed |
| ⚠️ 未验证 | 平台案例自带的工具资源（PDF 文本抽取、OCR、LaTeX 编译、Office 渲染等）与 Agent 代跑机制 | 机制存在但二期未真正用上，是最有价值的下一步 |

## 6. 投递节奏与资源分配

- **首日**：10 题各交一版精简骨架，目的是先把"通道 + 契约 + 落盘"跑通、拿到基线分；不求高。
- **稳态**：每 1–2 小时看一次榜单与出分；每轮只投 2–4 条；同一题一天不超过约 6 条。
- **资源分配**：先做"差距 ≤2 分"的题（重 roll 期望收益最高）；差距 2–5 分做"重 roll + 一次最小补丁"；差距 >5 分只做新设计、不追投。
- **停手条件**：门槛持续上涨且差距已 >5 分；平台队列明显拥堵（出分慢、失败率高）只备候选；同一版本连投 5 次仍无上尾提升，换设计或放弃。
- **记录**：每题维护一张「版本 → 分数序列」表，只记录相对变化；不因单次低分删版本——平台按历史最好分保留。

## 7. 失败模式与对策（二期高频）

| 失败模式 | 症状 | 对策 |
|---|---|---|
| 包不完整 | 只交 scripts 没有 SKILL.md；SKILL.md 引用的资源缺失 | 提交前脚本化检查"引用路径是否都存在" |
| 运行期脆弱 | `evaluation_error` / failed 频发 | 纯标准库、绝对路径自算、退出码恒 0、先 partial 后 finalize |
| 大而全 | 文件 27–28、240–300KB、脚本多 | 回到精简版，只加必要能力 |
| 证据不可核验 | 无 quote/locator、页码编造 | 逐字 quote + 定位；找不到就进 `pending_human` |
| 通道问题被当成质量 | trace 不可读导致 failed | 用 Agent 原生会话 JSONL 作为 trace |
| 误判版本 | 单次低分就改方向 | 同包重 roll 3 次再判断 |

## 8. 自检清单（复盘或开赛前）

- [ ] 能说出 10 题的分类与每题核心产物；
- [ ] 知道五维分值，且能对任一产物指出它对应哪个维度的哪个子项；
- [ ] 计划里有"首日基线 + 重 roll + 小补丁"三段，而不是只做一次大版本；
- [ ] 每个候选包都满足：唯一入口 SKILL.md、引用文件齐全、纯标准库、先落盘、退出码 0；
- [ ] 提交通道用原生会话 trace，并已验证可读；
- [ ] 记录表只保留分数与相对变化，按历史最好分决策。
